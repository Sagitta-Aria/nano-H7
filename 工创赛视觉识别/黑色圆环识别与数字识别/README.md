# 黑色圆环、中心数字识别与阈值调整

更新日期：2026-10-17。当前在黑色圆环检测的基础上，加入每个圆环中心附近的单数字 **1、2、3** 识别。支持多个不同心圆环，同心环合并为一个目标，允许斜拍椭圆和一定程度的轮廓畸变。检测后新增圆心距离过滤：**圆心直线距离不超过 100 像素时，只保留面积较大的圆环**。每个保留目标在原始画面上显示编号、中心、dx/dy、数字及置信度。

## 启动

- **统一入口**：双击“启动识别.cmd”，同时运行圆环识别、中心数字识别、阈值滑块和分割预览，拖动滑块实时生效。
- 原“启动圆环阈值调整.cmd”保留兼容，运行相同功能，无需在两个程序之间切换。

默认使用摄像头 1，请求 **1280×720、30 FPS、MJPG**，检测工作图默认最大宽度 **960**。实际尺寸、格式及驱动报告的帧率在终端显示；画面顶部显示采集尺寸、主循环处理 FPS、实际格式（应为 MJPG）和 Detect width。摄像头采集、截图及结果画面保持原始尺寸，圆心、轮廓、面积和像素差会换算回原图坐标。

在本文件夹的 PowerShell 中也可运行：

~~~powershell
.\.venv\Scripts\python.exe -B black_ring.py --camera 1
.\.venv\Scripts\python.exe -B ring_thresholds.py --camera 1
~~~

black_ring.py 管理相机、圆环检测、阈值滑块和显示；ring_thresholds.py 是同一程序的兼容入口；ring_digit.py 管理圆环中心取图、后台识别及目标间的结果匹配，也可直接运行；digit_core.py 管理数字模型、前景预处理和防闪烁投票。其他颜色及二维码程序仍引用这里的 .venv，请保留本目录及环境路径。一次只运行一个占用摄像头的程序。

## 圆环中心数字识别

只向数字模型提交已经检测到的圆环中心区域；没有圆环就不提交识别任务。每个独立目标分别识别，同心环仍只反馈一个目标。数字区域默认取孔洞直径的 **75%**；存在内层同心线时，先在局部图中寻找更内侧的孔洞，再排除环线和外围背景。局部灰度阈值仅从真实孔洞像素估计，并把纸面统一成白底，避免阴影中的灰纸与外部补白形成干扰。斜拍椭圆仅在 192×192 的 OCR 小图中近似校正，不改变实时画面的几何形状，也不改变圆心和 dx/dy。

每个圆环旁显示 `Digit: 2  confidence: 0.98`。尚未确认时显示 `Digit: confirming...`，无有效数字时显示 `Digit: --`。画面顶部显示处理 FPS、相机格式、中心区域比例和最近一次 OCR 耗时。终端的 rings 列表在原有坐标字段之外增加 digit、confidence、candidate 和 ocr_ms；没有确认结果时 digit 为 None、confidence 为 0。

数字识别使用一个后台线程，最多一个任务在运行，不堆积旧帧。多个圆环轮流提交；相邻帧根据位置和面积匹配缓存，画面上的 R1/R2 仍按当前帧从左到右编号。圆环消失或切换摄像头会清除对应缓存，并丢弃尚未返回的旧结果。圆环检测与坐标反馈继续逐帧执行。后台识别仍消耗 CPU，速度以当前画面上的 FPS 为准。

沿用之前的限制：只接受完整单字 1/2/3；不把字母强制改成数字，不从多位数中挑选一位。数字 1 保留较低阈值 **0.30**，2/3 为 **0.60**，并保留细长 1 的留白补偿。默认最近 7 次结果中至少 3 次一致、支持比例至少 65% 才确认或切换；缺少匹配结果达到 0.6 秒后清空，减少短暂漏识别造成的闪烁。

| 参数 | 默认值 | 调整用途 |
| --- | --- | --- |
| --confidence-one | 0.30 | 数字 1 的最低置信度；提高可减少误识别 |
| --confidence | 0.60 | 数字 2/3 的最低置信度 |
| --digit-roi-scale | 0.75 | 相对孔洞直径的中心区域比例，范围 0.30–0.95；数字较大或偏心时适当增大，环线干扰时减小 |
| --digit-interval | 0.06 | 两次后台任务启动的最小秒数，适用于全部目标；增大可降低 OCR 负载，但数字刷新变慢 |
| --digit-confirm | 3 | 确认数字所需的最少一致次数；减小会更快，也更容易闪烁 |
| --digit-window | 7 | 投票窗口长度，至少为 confirm；按 OCR 结果次数计量 |
| --digit-hold | 0.6 | 缺少支持结果时的保留秒数；圆环消失时立即清空 |
| --no-digits | 关闭 | 只检测圆环，不加载模型 |
| --digits | 所有入口开启 | 启用数字识别，与圆环滑块调参同时运行 |

~~~powershell
# 默认圆环 + 数字识别，两个命令使用相同实现
.\.venv\Scripts\python.exe -B black_ring.py
.\.venv\Scripts\python.exe -B ring_digit.py

# 数字较大时扩大中心识别区域
.\.venv\Scripts\python.exe -B black_ring.py --digit-roi-scale 0.85

# 降低后台 OCR 负载
.\.venv\Scripts\python.exe -B black_ring.py --digit-interval 0.10

# 只识别圆环，保留阈值滑块
.\.venv\Scripts\python.exe -B black_ring.py --no-digits

# 只显示识别画面，隐藏阈值滑块及分割预览
.\.venv\Scripts\python.exe -B black_ring.py --no-debug
~~~

上述数字选项由启动参数指定，不写入 ring_thresholds.json。离线单张图片直接返回一次识别结果，不进行时间投票。

## 阈值调整与保存

默认在同一个程序中打开两个窗口：

- Black Ring Targets：实时原图、各圆环中心与坐标差、数字及置信度、当前阈值、FPS、保存状态。
- Black Mask：六组滑块；下方从左到右为全局黑色分割、局部黑色分割、Canny 边缘图。

黑色分割中环带应为白色，孔洞应与环带分离。推荐先调灰度和面积，再调边缘、圆周支持比例及形状容差。

滑块默认开启，不需要额外启动调参脚本。--no-debug 可隐藏滑块和分割窗口，--debug 显式开启；无论是否显示滑块，圆环和数字识别保持运行。分割预览继续复用检测结果，最高默认 10 次/秒刷新，圆环检测仍逐帧进行。

| 滑块 | 源码默认值 | 含义与建议 |
| --- | --- | --- |
| Black max | 140 | 黑色灰度上限 0–254；黑环偏灰漏检时提高，暗背景误检时降低 |
| Min area px2 | **50000** | 外环包围面积下限，包含孔洞，单位为原始画面像素平方；保留你当前源码中的 50000。小环漏检可降低至 1000–5000，小目标误检时提高 |
| Canny low | 40 | 边缘低阈值 0–254；淡线漏检时降低 |
| Canny high | 120 | 边缘高阈值 1–255，自动保持大于低阈值；杂边多时提高 |
| Coverage % | 60 | 边缘路径的黑色环带和内外亮度支持比例，范围 40–100；断口漏检时尝试 50，误检时提高 |
| Shape tol % | 20 | 相对拟合椭圆的形状误差容差，范围 5–30；20 对应 0.20。畸变漏检时尝试 25，误检时降低 |

面积滑块下限为 1，上限默认 100000；启动初值更大时自动扩展。阈值始终以原始采集像素平方计量：例如 1920×1080 缩小为 960×540 检测时，程序自动把 50000 换算为工作图的 12500，再把结果面积乘回 4，不需要手工修改滑块值。面积和坐标差随采集分辨率改变。同心环按整体外边界反馈，一个独立目标只显示一组坐标。

所有入口使用相同按键（先选中任一程序窗口）：

- **S / P**：保存当前六项阈值到本目录 ring_thresholds.json，画面提示“Thresholds saved”。
- **R**：恢复源码默认阈值（包括面积 50000），只改变当前运行；继续按 S 才会写入文件。
- **F**：将原始画面和三联分割图保存到 captures，使用时间戳避免覆盖。
- **C**：切换摄像头 0/1。
- **Q / Esc**：退出。未保存的调整不会自动覆盖参数文件。

S 统一改为保存阈值；保存现场图片请按 F。

所有入口自动读取同一份 ring_thresholds.json。参数优先级为：**命令行显式参数 > 保存的 JSON > 源码默认值**。没有文件时使用源码默认值；格式或数值不合法时提示错误。首次保存后才生成文件，只保存六项检测阈值，摄像头编号、宽高、请求帧率由启动参数指定。

~~~powershell
# 显式调整面积，并进入滑块调参
.\.venv\Scripts\python.exe -B ring_thresholds.py --min-area 3000

# 使用另一份参数文件，按 S 保存到该文件
.\.venv\Scripts\python.exe -B ring_thresholds.py --config .\my_ring_thresholds.json

# 跳过读取已保存参数，按源码默认值启动
.\.venv\Scripts\python.exe -B black_ring.py --no-config
~~~

保存失败时终端显示原因，画面提示“Save failed; see terminal”；参数通过临时文件替换方式写入。

## 坐标与检测规则

R1/R2/... 按当前帧从左到右编号，不是持续跟踪 ID。每个有效独立圆环均显示中心、连线和坐标差，终端每半秒输出 ring_count 和 rings 列表。没有圆环时输出空列表。

先合并同心观测，再按原始采集坐标执行 **100 像素圆心距离过滤**，最后编号并进行数字识别。距离为 `sqrt((x1-x2)^2 + (y1-y2)^2)`，恰好等于 100 也过滤小环；例如横向差 60、纵向差 80 时距离为 100。多个目标按面积从大到小筛选，只与已保留目标比较；面积相同时按圆心位置确定保留一个。被过滤的小环不绘制、不输出坐标，也不参与数字识别，保留大环的中心不做平均。超过 100 像素的目标继续分别反馈。阈值固定在 black_ring.py 的 NEARBY_RING_DISTANCE = 100，不受检测工作图宽度影响，也不写入阈值 JSON。

~~~text
dx = 圆环中心 x - 画面宽 // 2
dy = 圆环中心 y - 画面高 // 2
~~~

右、下为正，左、上为负，单位像素。按实际采集尺寸计算中心，1280×720 下为 (640, 360)。排除实心黑圆和明显饱和的彩色环；画面保持原始几何形状，仅叠加文字与边界。

支持轻微畸变，椭圆短长轴比最低 0.25；这不等于完成镜头标定或去畸变。目标需完整入镜，严重遮挡、相互重叠、反光和背景过暗仍可能漏检。当前没有毫米换算或串口发送。

## 检测算法的帧率优化

默认 720p 采集、最大 960 像素宽的工作图逐帧检测，再把结果换算回原图。既不放大低分辨率输入，也不跳过检测帧。保留灰度/中性色复用、OpenCV 通道运算和候选局部区域核验，OpenCV 最多使用 4 个线程。

调参窗口直接复用本次检测的两张分割图与 Canny 图，省去第二次处理；三联预览宽度最多 999 像素，默认最高 10 次/秒刷新。圆环和坐标仍每帧检测，滑块变化会立即刷新分割图。未越界的滑块不再每帧重复设置。

在本机同一张 1920×1080 合成图上，包含 3 个独立目标及一组同心环，4 个 OpenCV 线程、预热后 20 次处理的中位数：

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 检测并绘制结果 | 46.6 ms | 16.8 ms |
| 同时生成调参预览 | 78.7 ms | 16.9 ms |

以上属于历史合成图测试，不包含真实相机采集和窗口显示，不能直接作为 USB 实测 FPS。请求帧率及驱动属性也不等于处理 FPS，真实设备测量见上一节，运行速度请以顶部 FPS 为参考。

缩小检测图可能损失细线和小目标，圆心与原尺寸检测也可能相差少量原图像素。当前 1080p 合成多目标检查中，960/1280 工作宽度的中心误差不超过 2 像素。小环、细线漏检时可提高检测宽度或使用 0 恢复原尺寸；源码最小面积仍保留 50000。

~~~powershell
# 默认：720p 采集，960 像素宽工作图检测
.\.venv\Scripts\python.exe -B black_ring.py

# 更小工作图，优先速度；请检查目标是否仍能稳定检出
.\.venv\Scripts\python.exe -B black_ring.py --detect-width 640

# 保留更多检测细节，或完全使用原图
.\.venv\Scripts\python.exe -B black_ring.py --detect-width 1280
.\.venv\Scripts\python.exe -B black_ring.py --detect-width 0

# 调参预览最高 15 次/秒；检测依然逐帧执行
.\.venv\Scripts\python.exe -B ring_thresholds.py --debug-fps 15
~~~

--detect-width 为 0 或至少 160 的整数，--debug-fps 为有限正数。两项是运行选项，不写入阈值 JSON。修改前的运行代码和说明在“清理备份/黑色圆环识别与数字识别/纯圆环提速前_20261017”。

## 依赖、来源与备份

圆环部分依赖 OpenCV、NumPy；数字部分使用 ONNX Runtime，以及 rapidocr_onnxruntime 随包提供的 PP-OCRv3 文字识别模型。本机 .venv 中已有全部依赖及模型，可以直接运行；新环境按 requirements.txt 安装。仅加载识别模型，不加载整图文字检测器或角度分类器；ONNX Runtime 限制为 2 个计算线程、1 个调度线程，并关闭空转等待，减少对实时圆环检测的影响。显式 --no-digits 时不加载数字模块。

数字模型来源：[RapidOCR](https://github.com/RapidAI/RapidOCR) / [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)，沿用 Apache-2.0 开源模型；本地代码直接进行等比例预处理和 CTC 解码。模型位于 .venv/Lib/site-packages/rapidocr_onnxruntime/models/ch_PP-OCRv3_rec_infer.onnx。
