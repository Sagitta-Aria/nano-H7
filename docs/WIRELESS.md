# v0.2.1 有线 / 无线双串口

两路均为 115200 baud、8 数据位、无校验、1 停止位、无流控。保留 USART1 的板载 CH340 COM Type-C；新增 UART7 的 PA8/PA15 排针连接无线调试器。

## ATK-HSWLDBG 接线

| 无线接收端串口引脚 | STM32 板端 | 作用 |
|---|---|---|
| TX | PA8（A08） | UART7_RX，STM32 接收 |
| RX | PA15（A15） | UART7_TX，STM32 发送 |
| GND | GND | 共地 |
| Vext | 板上 3.3V | 接收器配置为“输入”电压模式时，提供 IO 电平参考 |

接收器 USB 供电方式按其手册操作。若 Vext 曾设置成电压输出，先恢复输入模式再连接板上 3.3V，避免电源输出互接。测试前移除 TX/RX 回环短接线，两端保持配对。

电脑连接无线发送端，上位机选择它的串口（本机回环测试时为 COM28，重插后可能改变）。不要将 TTL TX/RX 接到板上 COM Type-C 的 USB 数据脚。COM Type-C 可同时用 USB 数据线直接连接电脑观察返回帧。

PA8/PA15 均使用 AF11，依据 STM32H743 数据手册 DS12110 Rev10 表 10（第 88–89 页）。PA15 不再用于完整 JTAG 的 JTDI；PA13/PA14 的 SWD 下载仍保留。原分配表的第三路超声波 U3 使用同一组 UART7，本版改用于无线，后续 U3 需要另选引脚。

## 双发的含义

- 两路均可输入协议命令，各有 1024 字节接收缓冲及独立组帧、超长帧丢弃、200 ms 半帧超时，字节不拼接混用。
- 任一路命令的应答都会发到 USART1 和 UART7。两路各自推进发送，单路 TX 等待超时不会阻断另一份应答；错误应答和重复请求应答也双发。
- HELLO 返回 `serial=dual`。Python 上位机无需改协议，只需选择串口。固件仍为请求/应答模式，不自动周期打印文本。
- 两路属于同一个控制会话，**只运行一个主动控制上位机**；另一端可用串口助手被动观察。当前没有多控制端仲裁，任一路新 PING 都会刷新共享心跳，因此不能用两个主动上位机独立检测各自断线。
- 两路共享最近 8 条命令的序号去重缓存。同编号、同正文跨端口重发不会再次执行运动；同编号、不同正文拒绝。缓存淘汰或 MCU 重启后的去重边界与原协议相同。
- `STAT` 的 `rx/rx_err/tx_err` 汇总两路串口计数。

## 烧录和测试

1. CubeProgrammer 选择 `firmware/build/robot_h743.hex`，不要选 Keil 工程 `.uvprojx`；下载并校验。
2. BOOT0 恢复正常启动位置，复位运行新固件。无线按上表连接，有线可同时接板上 COM Type-C。
3. 关闭占用同一串口的 XCOM，重启 Python GUI，刷新串口并连接无线发送端。
4. 确认 HELLO 显示 0.2.2，测试绿/蓝 LED 和资源查询，无需使能电机。
5. 如需观察双发，在串口助手中打开板载 CH340 对应端口，115200、8N1，只接收；无线 GUI 控制 LED 时两端应出现相同序号的应答。

手工握手用 ASCII 文本 `@1 HELLO*7DF0`，末尾发送真正的 LF（0A）或 CRLF（0D 0A）。该请求不会控制电机。

2026-09-20 已在 COM28 完成无线接收器 TX/RX 短接回环：3 组随机数据逐字节一致。这仅证明当时的无线链路；本版 UART7 固件尚未执行烧录或 STM32 实机联调。
