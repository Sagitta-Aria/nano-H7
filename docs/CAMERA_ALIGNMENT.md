## 圆列搜索与顺序识别

在“摄像头1”选择“黑色圆环”，设置“圆列搜索与顺序识别”，点击“校准点1并定距移动到2、3”。“点间距 · 脉冲”默认 **2200**，可填入1～100000的整数并点击保存；适用于独立入口和坐标巡航，运行中使用启动时的配置快照。旧配置加载时补全2200，保存后写入 `camera_alignment.json` 的 `ring_sequence.spacing_steps`。摄像头、H743 和 H723 的连接及使能条件与色块模式相同。

- `X` 定义为搜索中心两侧各 X 脉冲，默认 **2000**。先从 0 向后到 −X，再向前到 +X，最后回到 0；找到双圆即结束搜索。一轮仍无双圆则停车报错。步长默认 **200**，搜索及转向速度 **300 step/s**。
- 搜索运动中持续读取新帧，连续三帧看到同帧双圆便发送 `CHASSIS HALT`；确认运动编号、空闲状态后，用 `total-remaining` 记下实际已执行的脉冲。再等待 100 ms，用停车后新帧重新确认连线；不会用运动中的角度直接转向。每段自然结束也进行同样的停车后观察。所有位置都是下发脉冲的估计，未融合编码器或轮滑修正。
- 只连接**同一帧**内两个不同圆心；多种阈值和同心套环会去重，同心圆不能充当两个位置。NX 屏幕绘制圆心连线。分别移动后看到的单圆不会拼接成直线。
- 连线换算使用摄像头安装角，默认左转 **+90°**，选择最近的平行方向；稳定三帧后发起 H723 闭环转向，单次最多 **15°**，每次转完重看双圆。平行容差默认 **2°**，连续三帧合格后进入数字识别。
- 尚未摆正时，旋转中和停车后都持续检查双圆。连续三个新鲜帧丢失双圆，先停止当前旋转并确认原操作编号及四轮空闲，再以当前姿态为中心重新执行 `0 → −X → +X → 0` 往返搜索。后退途中看到双圆不会恢复摆正；只有向前搜索过程中连续三帧看到双圆，才停车确认，再完整前进 **500 脉冲**。这段前进不被双圆检测提前截断，可能超出搜索边界 500 脉冲；完成并静置 100 ms 后，仅用新的停车画面重新计算连线并摆正。仍丢圆则再次进入恢复搜索；一轮搜索失败或总流程超过 300 秒仍会停车。短暂一两帧漏检不会触发恢复，旧帧不能累计丢失或重获票数。
- “1 位于车后”作为初始摆放约束，不由无方向的直线猜测 180° 朝向。寻找 1 只向后，画面中实际看到的 2/3 会显示出来，但不会推进顺序。寻找点1以该阶段起点为基准最多移动 X 脉冲；识别不到时每处先观察至少五帧再移动。运动中连续三帧看到点1会先停车，停车后再次确认。
- 停车后三个新帧确认点1后，保持该 OCR 目标，重新记录当前陀螺仪参考，并复用色块模式的视觉 PID、相机安装角与四轮混合，向 `(圆心X+偏移X,圆心Y+偏移Y)` 靠近，默认偏移 `(0,+30)`。连续三帧进入死区、航向合格且四轮实际停止后，点1校准完成。点1靠近时丢失数字立即请求零速度，持续三秒则停车报错；靠近最多30秒。
- 点1完成后退出识别控制流，立即沿摆正后的车身前方移动一个点间距到点2；完整到达后立即前进同样距离到点3。点2、点3不重新OCR寻点或运行视觉PID；移动沿用圆列速度、陀螺仪直线保持和原加速度。到达依据为同一运动编号、`done`、四轮空闲和剩余脉冲为0；单独ACK不能算到达，画面也不会截断这段移动。独立入口到点3结束；巡航入口在点3确认到达后，同距后退到点2后执行出站。
- 数字 OCR 仅在摆正后加载，识别真实圆环孔洞，NX 使用现有 TensorRT 数字模型。点1完成后使旧帧、旧线程错误与旧回调失效；后续定距阶段不再依赖新相机帧。到达记录的 `positioning` 区分点1的 `vision` 与后续 `fixed_spacing`，后者不伪造OCR圆心或帧号。不附加抓取动作。
- 整个流程最多 300 秒；单个运动有独立超时。停止、连接断开、失去使能、运动或视觉异常都会取消流程并停车。

安装角变换要求图像方向能代表地面方向。**有明显倾斜透视时，像素连线角不等于地面角**；当前未加入相机内参/地面单应性标定，需实车核对或先完成地面校正。该实现仅接受同帧双圆，无法覆盖摄像头视野始终只能容纳一个圆的布置。

圆环模式的中心偏移、PID、死区和最低速度仅用于点1靠近；搜索、点间移动和转向使用圆列速度。页面显示阶段、当前目标、已到达顺序、搜索脉冲或相对点1的脉冲位置、点间距、等待倒计时和点1靠近误差。下文的速度 PID 与租约说明也适用于点1靠近。

摄像头相对底盘向左安装 90°，对应“摄像头安装角”默认 `+90°`（左旋为正，可在“视觉 PID 与启动速度”中调整）。视觉 PID 先输出相机方向的靠近速度，再换算为车身方向，最后叠加陀螺仪航向纠偏并解算四轮速度。`+90°` 时：`车身向右速度 = -相机向前速度`，`车身向前速度 = 相机向右速度`。安装角不加到陀螺仪目标航向上；目标偏移 `(X,Y+30)` 和死区仍在相机坐标中计算，方向反转开关也作用于旋转前的相机方向。

已有配置缺少安装角时读取为 `+90°`，保留原 PID、速度、偏移等参数，不自动重写配置文件；点击保存后持久化安装角。

## 操作

1. NX 显示器默认全屏显示摄像头一实时画面和数字识别结果；右侧可点“数字/色块”切换预览算法。服务启动自动打开摄像头，优先使用记住的设备及原生 1280×720；本地识别不会启动车辆运动。
2. 网页进入“摄像头1”，来源选 Nano。选择色块及颜色，或黑色圆环，设置目标偏移。
3. “预览 NX 识别 · 不移动”读取一次连续识别结果。网页“拍照”只用于查看，不参与识别或控制。
4. 设置速度上限、死区，展开“视觉 PID 与启动速度”可调 PID、最低靠近速度和加速度。
5. 连接并校准 H723，停止其他任务，正常使能车辆后点击“开始车辆对准”。随时可停止。

默认值：速度上限 **2000 step/s**，最低靠近速度 **300 step/s**，加速度 **6000 step/s²**，死区 **±5 px**，Kp **10**、Ki **0**、Kd **0.15**。Ki=0 时积分关闭，界面允许调整全部三项。最低速度不允许大于上限。

NX 全屏窗口恢复数字/色块触屏按钮、数字与置信度或色块名称、FPS、原图目标中心、控制点及 X/Y 偏差。黄色十字为画面中心，绿色圆为目标中心，紫色十字为加偏移后的控制点；坐标始终使用相机原图像素，默认控制点 `(X,Y+30)`。过期结果隐藏，不保留旧坐标冒充实时结果。

待机预览复用原 GPU 数字/色块算法，在 640×360 预览图的整幅画面内识别，不再限制中央矩形或裁掉底部；结果映射回原图像素。旧的 ROI 环境变量不再限制此入口，画面不再绘制识别范围框。车辆对准也使用完整原图。右侧按钮只切换本地预览，车辆对准以网页保存的目标类型与颜色为准。对准或单次 NX 预览期间暂停本地预览推理，画面显示 `ALIGN` 和控制器实际使用的原图识别结果；结束后恢复原来的数字/色块预览。Esc/Q 关闭本地窗口，不停止对准或关闭相机；重启服务恢复全屏。关闭网页不影响本地显示。

## 连续闭环

```text
ex = X + 偏移X - 画面中心X
ey = Y + 偏移Y - 画面中心Y
右移速度 = PIDx(ex)
前进速度 = -PIDy(ey)
旋转速度 = 航向 P(启动朝向 - 当前朝向)
```

X/Y 两轴同时纠正。积分与微分只使用采集时间递增的新帧，积分限幅并在输出饱和时停止积累，微分滤波；进入死区、误差跨零时清除相应积累。远处速度较高，近处按剩余像素逐渐降低最低靠近速度，避免目标旁边仍强制300 step/s。

控制器以图像中的接近速度、当前帧延迟、50 ms命令周期和估计减速时间预测是否即将进入死区，必要时提前发零速。越过死区到另一侧时，本次对准对应轴的速度上限减半，防止不断全速反向；新一轮对准恢复配置上限。此预测不需要像素到脉冲标定，但仍是估计，不证明真实制动距离。暂时零速不等于对准完成，必须连续新帧的实际像素误差进入死区，并确认四轮停止、航向合格后才结束。停车确认与航向查询按查询次数交替，不再依赖图像帧号奇偶，避免某些帧率下始终无法确认停车。

纯车体左/右平移的四轮都应转动；斜向运动或平移与航向修正叠加时可能有对角两轮目标为零。低速咔咔声还可能与驱动细分、低频共振、供电、电流和负载有关，软件不能根据声音确认原因。合成延迟/加减速测试不能代替实车调参或保证无过冲。

NX 约每 50 ms 更新航向与四轮目标。轮序为后左、后右、前左、前右，右移/前进/顺时针速度为 vx/vy/w：

```text
M1 = vy - vx + w
M2 = vy + vx - w
M3 = vy + vx + w
M4 = vy - vx - w
```

之后应用与固件 CHASSIS 相同的电机反向掩码，并按四轮最大速度等比例限幅，发送 `WHEELS M1 M2 M3 M4 accel`。不再发送固定 10 脉冲或反复执行独立 TURN MOVE。涉及轮子反向时先四轮减速至零，查询确认实际停止后再反向。

换向停车使用速度指令代次：只有当前四轮零速度已经收到板端 ACK，才允许发起停车查询；返回的实际空闲状态还须对应同一速度代次，且当前仍处于 braking/settling，才能清除方向保护。旧的 idle 应答不能在新帧恢复运动后清除保护，旧零速度 ACK 也不能授权下一次停车。有限搜索切换到视觉靠近时重新清空停车证据。

H743 0.2.21 在减速到零、STEP 仍为高电平的收尾窗口，会拒绝新的 `WHEELS`，包含重复零速度。因此串口线程对同一指令代次的零速度只发送至首次成功 ACK；此后继续监督 250 ms 视觉租约、心跳和停车状态，但不重复零速度。非零速度、变化后的新指令仍正常发送，STOP/清除租约会清除缓存。停止后同方向恢复也必须先确认实际空闲，不能用新帧抢占 STEP 收尾。该兼容处理无需烧录或提高加速度。

`DISARMED_BUSY_OR_REVERSE` 是 H743 对四轮指令的拒绝，不代表低于最低速度，也不是 ZDT 驱动器告警；可能表示未使能、有限轨迹/停止仍占用车轮或未停稳反向。出现速度拒绝时，先保存原指令、当时的视觉、期望轮速、方向保护、速度代次、最近 80 条请求/应答以及板端缓存状态，再 STOP。记录追加至配置文件所在目录的 `logs/camera_alignment_faults.jsonl`，网页状态的 `fault_context` 也保留该现场。板端缓存和下发脉冲不等于 ZDT 编码器反馈。

两轴进入死区后立即请求零平移速度，连续三帧在死区内、航向合格且四轮实际停止才完成；正常完成保留使能。停止、丢失目标、断连或故障执行 STOP。

## 采集、显示与反馈时效

摄像头只有一个采集者，持续读取并只保留最新原始帧。本地显示与识别消费该帧，不重复打开设备。显示在相机进程主线程运行；识别在独立线程运行，只输出坐标元数据，不编码 JPEG。网页拍照另行请求 JPEG，并使用独立缓存。

识别结果使用 NX 单调时钟和帧编号，重复、启动前采集或超过 750 ms 的结果先丢弃。有效结果中断超过 750 ms，或采集时间超过 1.2 秒，则请求零平移速度；3 秒仍没有有效结果才结束并 STOP。没有有效视觉反馈时也不输出旋转速度。航向查询超过 600 ms、航向失效或来源重置会停止。

串口线程独立检查视觉速度租约：NX 控制循环每 50 ms 续期，超过 250 ms 未续期即 STOP。即使串口线程仍在发送 PING，也不能保持失去控制循环的旧速度。停止清除租约，旧代次结果和应答不能恢复运动。一次对准最长 60 秒。

## 模块与配置

- `host/camera.py`：单一原始帧采集、独立识别、NX 全屏显示和手动照片。
- `host/camera_monitor.py`：复用旧 GPU 数字/色块算法和触屏按钮，显示实时识别信息，不生成运动命令。
- `host/vision_alignment.py`：`VisualPID` 和 `mix_wheels`；现有任务的标定接口保持兼容。
- `host/camera_alignment.py`：独立闭环执行、航向反馈、换向及完成确认。
- `host/ring_sequence.py`：有限脉冲搜索、同帧连线转向、1/2/3 顺序状态机。
- `host/ring_perception.py`：圆环去重及按阶段加载的孔洞数字 OCR。
- `host/transport.py`：最新速度缓存、过期租约与 STOP。
- `host/static/camera_alignment.js`：参数和状态，不生成车辆命令或上传图片。

参数保存在 `host/camera_alignment.json`。旧文件加载时补全 PID 字段，显式保存才写盘。NX 部署的 `h743-web.service.d/camera-display.conf` 提供 DISPLAY、XAUTHORITY、`H743_CAMERA_DISPLAY=1` 和 `H743_CAMERA_PYTHON=/home/a/vision-env/bin/python`；相机子进程使用原 GPU 视觉环境，主服务仍用系统 Python。普通桌面/测试环境不会隐式打开相机。

接口维持 `/api/camera/vision/state`、`config`、`recognize`、`start`、`stop`。识别预览不接收本机图片；旧 `vision/frame` 入口无识别 JPEG 可返回。

# 坐标巡航圆列子任务（2026-10-16）

在坐标巡航路线表勾选“视觉挂起”，下方选择子任务 1。子任务 2、3 保留为独立动作类型；在任务 JSON 的对应路线段配置动作后才能使用，不会默认为空任务执行。

子任务 1：挂起到点 → 同帧双圆搜索和姿态校准 → 点1识别并靠近校准 → 定距前进到2、3 → 同距后退到2 → 向车身右侧平移 → 从更新后的坐标重新规划并继续剩余巡航。点间距取摄像头1保存的设置，默认2200脉冲；数字间不追加固定等待，抓取动作尚未接入。

每个路线段独立保存 `task: 1`、`outward_steps`（默认 400）、`right_steps`（默认 800）。首次完整前后搜索失败后，朝最近地图外边界对应的车身方向移动 `outward_steps`，再完整搜索一次；再次失败停车，避免无限向外移动。零外移配置表示不补搜。

搜索和 1→2→3→2 的移动不累计入巡航坐标。点1视觉校准后，按设定点间距完成2、3及返回2的定距移动，再由 NX 显式恢复该巡航站点的 XY 作为地图基准，保留出发时的地图航向，只把随后的右移计入位置。地图虚线标记右移终点，实时红点跟随右移，下一段路径从此终点重新计算。例如下一目标距离 2000，向目标方向右移 800 后，新段只需前进 1200。

通用交接要求 H743 的 `NAV ALIGN suspend=1` 能力：NX 发 `NAV SUSPEND` 取得底盘，完成数字 2 后发 `NAV POSE x y` 设置参考，然后用原有 `CHASSIS STRAIGHT RIGHT` 退出。NX 验证同编号有限运动完成、剩余 0、轮轴静止、导航积分与计划终点误差不超过 2 脉冲加行程 2%，再发 `NAV RESTORE x y`，重新上传剩余路线。MCU 不接收数字、补搜和右移参数，也不据视觉方向修改地图航向。真实航向对应的右移终点若明显偏离计划通道方向，NX 在右移前停止并报布局/姿态不一致。此为命令脉冲定位，非编码器测量或防滑校正。NX 保持用户看到的原路线段号。

该接口用于任意外部定位或自主控制任务。旧接口不能直接组合：`waiting` 仍保持航向并占用轮轴，独立运动则使导航 ready 失效；`NAV RESET` 要求解除使能且会重建地图航向。新增接口只补这处通用能力，全部圆列业务在 NX。

旧固件会在启动前明确拒绝圆列巡航子任务；独立相机对准仍可使用。保存配置不移动、不使能、不自动为现有站点分配任务。建议先在地图上检查右移后的通道位置；越出通道的配置会在启动前拒绝。



## 2026-10-20 严格平行判据与 C 点取证

保持现有同帧双环中心连线测角、camera_yaw 变换和现场视觉容差 0.4°；不要求三个圆同时入镜，不改变相机标定。校平须连续三个新帧均在视觉容差内，跨入或跨出容差会清空稳定计数。单次 TURN 完成容差取视觉容差一半（0.4° 对应 0.2°），范围夹至 0.01～10°；靠近保向容差取共享容差与该值的较小值。旧固件无法满足更严容差时明确拒绝，避免出现命令完成却没有转动。靠近时若双环再次测得角度超限，先确认刹停再校平。

更严格的反馈判据不能证明镜头畸变被消除。当前不做透视校正；是否平行及是否在后续移动中歪斜，需实车观察与日志共同确认。
