# 故障停车与恢复（v0.2.21）

正常的 busy 表示轴、巡航或转向仍占用轮组。停止全部可以取消当前任务和待发动作；fault 是已终止的故障结果，不应继续占用任务控制权。固件的步进定时超期和脉冲位置溢出会另外锁存，普通 STOP、页面刷新或串口重连不能清掉它。

上位机发现运动、底盘、巡航或转向故障后，取消当前自动任务、视觉请求及待发命令，停止全轴并清除持续行驶指令。原因留在任务错误和日志中。页面在解除使能或发现故障后释放本地行驶按键状态，避免已停止却仍被本地 busy 禁用。

恢复步骤：

1. 点击“停止全部 / 解除使能”，检查显示的具体原因并排除故障。
2. 等待全轴停止后点击“故障复位”。固件只在解除使能、全轴静止时接受，最后的 STEP 高脉冲未结束时拒绝。复位后仍停车，旧任务和旧路线不会恢复。
3. 若 M5/M6 在故障发生时运动，其脉冲位置仅供估计，参考变为无效。先将机构人工恢复至可确认的位置，再明确确认参考；操作本身不驱动电机。M5 页面“故障后人工确认深度”输入实际已到的标定深度，然后确认恢复参考。默认 0 只适用于物理最高点；若软件范围不含 0，必须使用范围内的已知物理标记。M6 解除使能后放在选定零位，再点击“当前位置设为零”（范围须包含 0），也可通过 `AUX REFERENCE 6 <known_position>` 恢复范围内已知位置。不得把卡住时的未知位置直接认作零点。
4. 将底盘实际恢复到 O 点位置/方向，再“建立 O 点”。复位不修改轮组脉冲累计值，但使旧导航参考和上传路线失效。
5. 明确使能，再启动新任务。相机、IMU、障碍物或机构参考仍未满足条件时，继续拒绝启动；复位不会伪造传感器正常或清除障碍物输入。

协议查询：

```text
MOTION STAT
OK cmd=MOTION_STAT v=1 latched=1 total=1 reason=step_deadline uncertain=17 active=0 armed=0
MOTION CLEAR
OK cmd=MOTION_STAT v=1 latched=0 total=1 reason=step_deadline uncertain=17 active=0 armed=0
```

`latched` 表示当前锁存；`total/reason` 是本次 MCU 启动内累计次数和最近原因，CLEAR 后保留。`uncertain` 按 M1～M7 的 bit0～bit6 标记故障时活动的轴；M5/M6 恢复参考后相应位清除。未受影响的辅助轴位置/参考、软限位、调参保留；串口重连的 LIFT INIT 不会恢复已经丢失的参考或偷偷重置位置。新协议使用独立查询，旧固件没有恢复能力时按钮禁用，上位机仍支持 STOP 和故障显示。

这是软件已检测故障的恢复流程。目前没有编码器、限位或驱动器故障输入，不能据此判断任意堵转、打滑、断电是否发生。复位只解除软件锁存，不能修复机械/供电或保证物理位置。

本地验证使用 Keil ARM Compiler 5 编译、Unicorn 执行实际 ARM 镜像、SIM 协议和 Edge 浏览器。`python -m tests.recovery_browser` 使用临时配置/随机本地端口；故障注入命令和 HTTP 入口仅存在于测试夹具，不进入生产服务。未烧录、未驱动实车。


## v0.2.28 IMU 暂停与退出审计

同会话 IMU 样本无效或过期：依赖航向的直线、独立 TURN、巡航（包括 NAV SUSPENDED 下的自动视觉任务）停车等待，`paused=1`。NX 保留编排状态，冻结任务、视觉和待应答预算；已收到的成功 ACK 仅缓存并消费一次，不重发已接受动作。恢复要求至少三个有效样本且跨度达到 100 ms；视觉速度不重放，须重新获取新帧与航向。暂停期间已启动的 M5～M7 动作可完成，不自动回退或重复放置。

本规则不覆盖独立手动 WHEELS，也不把所有退出条件改为自动恢复。独立视觉调试没有 NAV 挂起或有限航向任务时，仍可能由航向查询超时终止。

仍会退出：用户 STOP/ARM0/各控制器停止；运动故障锁存；MCU 心跳超时；真实串口断开或服务重启；IMU 会话改变使旧零点失效；路径/操作编号变化或外部抢占；未处于 IMU 暂停时的应答、视觉或任务超时；识别错误、搜索越界、颜色歧义；辅助机构参考、行程或软限位错误。B 点等待指定颜色且持续有新帧的既有无限等待行为保留。

PC 到 NX 的 SSH/Wi-Fi 断开不直接终止 NX 本地任务。NX 到 MCU/IMU 的设备链路故障须按以上边界区分，不能统一解释成网络断线。此修改只恢复同会话可继续的任务，不恢复已经 fault 的历史任务。
