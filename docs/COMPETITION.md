# 比赛启动与参数恢复（v0.2.27）

当前处于调试阶段，默认首页 `/` 和 `/debug` 均为完整调试界面。比赛专用单键页面只保留为后续方案，不再自动占用默认首页；正式切换需用户届时明确要求。参数保存与启动提速继续生效。

车辆放在已保存路线的起点并对准相应朝向后，按一次启动。默认 O 朝向 0°；v0.2.29 可在调试页保存 X 起点 `(0,28800)`、朝向 -180°，启动后先内移、转到 0°，从内移位置直接到 A，随后沿用原流程。连接时 NX 恢复已保存控制参数；按启动后确认设备和有效航向、解除旧使能、建立所选起点、使能、上传并执行路线。重复点击不会启动第二份任务。刷新或关闭网页不取消后台任务。程序重启不会自动重复上一场比赛。

比赛使用已保存的站点、路线、速度、加速度和站点任务。比赛运行快照将 `dwell_ms` 设为 0，到点任务完成后直接推进，不修改磁盘上用于调试的停留参数。只有调试用、没有关联动作的人工挂起会在本次运行中转为直接通过，磁盘配置保持原样；有视觉或机构动作的站点仍等动作完成后自动放行。首个视觉任务需要相机一时，启动流程自动打开已绑定相机。

## 航向偏差

原先行驶偏差超过 5°会进入 `heading_deviation` 故障，取消巡航。现在 5°是纠偏切换阈值：小偏差继续混合航向修正，大偏差暂缓平移、原地闭环纠正航向，然后从累计 XY 重算到当前目标的剩余向量。路径编号、动作编号、目标和地图参考系均保留。连续偏航可以连续恢复，不重新上传整条路线。

普通辅助直线和到站微调也不再因为偏差超过 5°退出控制。它们继续使用已有航向反馈调节轮速。向量终点修正不再因固定三次计数而报错，仍按当前动作时间预算执行。明确 STOP、失去航向反馈和硬件输出故障的处理保持有效。

## 参数保存

Web 下发的 `TURN CONFIG`、`CHASSIS CONFIG`、`LIFT DIR` 收到板端成功应答后，会把完整参数原子写入与 `navigation.json` 同目录的 `control_settings.json`。

- 转向 P、完成容差、最低转向速度：恢复完整三元组。
- 底盘四轮反转掩码：恢复已接受的值。
- 升降向下方向：重连时先读取板端；相同值不重复设置，不重置机构位置。

重连会恢复上述设置，比赛启动会等待恢复应答。参数保存尚未完成或写盘失败时，重启接口会返回具体原因，避免“页面显示已应用但重启后丢失”。调试页首次加载以服务端已保存转向参数为准，不再拿浏览器旧草稿冒充已生效参数。

路线、机构预设、抓放和视觉参数继续使用各自现有 JSON。部署清单只更新代码，不覆盖车上的 JSON。尚未提交的编辑框草稿不属于板端已应用参数。
