# NX 面板一键启动

NX 上电后整屏直接进入这个启动页，日常比赛不需要打开浏览器或调试页。它只调用本机 HTTP 接口，不直接碰串口，所以启动页本身出问题不会让车动。

## 界面

- 顶部：连接状态（H743 已连接/未使能/固件版本），上位机没起来时显示"上位机未响应"。
- **巡航起点**：O 点 / X 点 两个大按钮。X 需要两个条件同时满足才可选——固件 `INFO` 报 `nav_reference=1`（0.2.29 起），并且已保存的巡航配置里有名为 `X` 的站点。
- **开始**：以 `full_flow=true` 调用 `/api/competition/start`，带上所选起点。启动后自动连接设备、恢复已保存参数、建立所选起点、使能、跑完整两轮搬运，全程沿用已保存的站点坐标、姿态、抓放与视觉参数。
- **停止**：只在运行中出现，发送 `STOP` 并取消任务。
- 底部：当前阶段（连接设备 / 恢复参数并建立起点 / 路线执行中：抓取与放置 …）与错误原因。

## 起点选择的口径

选 O 时车必须放在地图原点、车头朝 0°；选 X 时车必须放在 `(0, 28800)`、车头朝 -180°。启动页只负责把选择传给上位机，**不会替你移动车辆**。X 出发的第一段是"向场地中心内移 → 转到 0° → 直接从内移位置平移到 A"，之后与 O 出发相同。

选择只对本次运行生效，不会改写 `host/navigation.json` 里已保存的 `start_station`；调试页看到的仍是它自己保存的默认起点。

## 与摄像头窗口、任务码卡的关系

运行期间启动页会**主动让出最前层**（取消置顶并下沉），摄像头1 的全屏预览和二维码任务码卡才能显示；任务结束、故障或停止后启动页自动回到最前。两者不会互相遮挡。

## 开机自启

用户级 systemd 单元 `~/.config/systemd/user/h743-launcher.service`，模板在 `tools/h743-launcher.service`：

```bash
systemctl --user daemon-reload
systemctl --user enable --now h743-launcher.service
systemctl --user status h743-launcher.service
journalctl --user -u h743-launcher.service -n 50
```

需要在图形会话里运行，所以单元带 `Environment=DISPLAY=:0`；用户已开启 linger，退出 SSH 后仍保持。

## 排查

| 现象 | 含义 |
|---|---|
| 顶部"上位机未响应" | `h743-web.service` 没起来或端口不是 8770，可用 `--url` 指定 |
| "设备未连接" | 串口没连上，检查 H743/H723 的 USB |
| X 点灰不可选 | 固件不是 0.2.29+，或配置里没有 X 站点 |
| 按开始无反应且底部有红字 | 上位机返回的具体原因，例如参数不可执行、设备未就绪 |
