# 达妙 H723 USB 陀螺仪（本地与 Nano 上位机）

目标是达妙 **DM-MC02 / STM32H723VGT6 / BMI088**，通过独立 USB CDC 虚拟串口接入。
Web 与 Tk 上位机都新增“陀螺仪 · H723”页，可与 H743 同时连接，各自使用独立串口。
本地与 Nano Web 上位机均支持 H723 独立 USB 虚拟串口。Nano 的部署与自动连接
运行方式见 [JETSON.md](JETSON.md)，使用 H723 1.1.1 固件。

## 运行与连接

1. 为达妙板烧录 `D:\stm32H7\projects\CtrBoard-H7_USB_Gyro\release\DM_MC02_USB_Gyro.hex`。
   当前固件身份版本为 **1.1.1**，旧版只有 IMU1 输出、没有握手的固件会被拒绝。
   固件使用 Keil Arm Compiler 5.06 update 7 编译；用户授权后已烧录并验证 Flash 读回与复位运行。
2. 用数据线连接达妙板 USB Type-C 与电脑 USB 主机口。
3. 在 `D:\stm32H7\stm32H743IIT6` 下运行：

   ```powershell
   D:\python2\python.exe -m host.webserver
   ```

   或双击 `host/run_web.bat`。HTTP 页面只需 Python 标准库，实际串口连接还需要
   `python -m pip install -r host/requirements.txt`。Tk 后备入口为 `python -m host.gui`。
4. 打开“陀螺仪 · H723”页，刷新设备，明确选择候选端口，点击“握手连接 H723”。
   不用顶部 H743 连接按钮来连接达妙板。
5. 板子保持静止约 2～3 秒，校准完成后显示有效姿态。状态/校准失败时不显示实时数值。

## 图形与单位

- 最近 15 秒 Roll/Pitch/Yaw 姿态曲线，横轴时间 s，纵轴角度 °。
- 最近 15 秒 X/Y 加速度曲线，横轴时间 s，纵轴加速度 m/s²。
- XY 加速度矢量与最近采样点；两个方向使用相同的每像素数据比例。
- 默认显示去重力后的车体线性加速度，也可切到含重力的加速度计值。

沿用原固件安装映射：车体 X 向前、Y 向左、Z 向上。XY 图不估算位置。
BMI088 无磁力计，Yaw 是相对航向，长时间会漂移。
超过 0.5 秒没有新的采样则标记过期、实时数值清空；超过 3 秒关闭连接。
失效帧不绘制为零，也不与后面的有效曲线直接相连；断开保留历史，重新连接清空历史。
“清空本页图形”只清除当前浏览器的图形，不清除板端数据。

## 避免误识别

枚举串口时只读 USB 元数据，不逐个打开串口试探。
只有 VID/PID **0483:5740** 的 ST USB CDC 出现在 H723 候选列表，且必须有 USB 序列号。
本地默认需要明确选择候选端口；Nano 启用 `--auto-devices` 时自动尝试候选设备。
USB 序列号在打开前和握手后再次核对，防止串口号被重用。
上位机先被动收到完整 IMU1 行，才发送随机挑战：

```text
IMU? <16 位小写十六进制 nonce>\n
IMU! <相同 nonce> board=DM-MC02 mcu=STM32H723VGT6 sensor=BMI088 protocol=IMU1 fw=1.1.1 uid=<24 位十六进制芯片 UID>\r\n
```

响应必须匹配板型、MCU、传感器、协议、随机挑战及有效非零 UID，之后才发布测量值。
串口名称、厂商 VID/PID 或 IMU1 输出本身都不足以确认设备。
这用于防止普通设备误识别，不是对恶意仿冒设备的密码学认证。
H723 通道不会发送 H743 的 HELLO/PING/STOP/ARM 或电机命令；H743 入口排除 ST CDC 端口。
多浏览器页面沿用原来的单控制页规则，只读页面可以查看图形，不能连接或断开设备。

2026-10-11 已用真实 DM-MC02 验证：修复版 1.1.1 在 SRAM 临时运行后枚举为 COM40，
随机挑战确认 STM32H723VGT6/BMI088 身份，Web 上位机在 10.046 秒接收 1006 帧有效
数据（约 100 Hz）、无解析错误，姿态及 XY 加速度图已绘制。COM30（SEGGER/J-Link）
仍被候选过滤排除。实物截图与记录在 `D:\stm32H7\tmp\h723_usb_debug_20261011`。
用户授权后已正式烧录 1.1.1，Flash 读回与发布文件完全一致。独立复位后的真实
Web 检查再次通过：10.031 秒接收 1006 帧有效数据、坏帧数 0，姿态/加速度曲线和
XY 矢量图坐标轴均通过检查。随后数据线移到 Nano，枚举为 `/dev/ttyACM0`，
新版服务自动握手并绘图；两块板主动断开后均自动重连，H723 约 100 Hz、坏帧 0。
已验证复位启动，尚未另做断电上电测试。

## Nano 自动连接

Nano 服务启用 `--auto-devices`，不再默认连接模拟板。后台每 2 秒重新枚举一次，
不依赖浏览器开启；H743/H723 独立自动握手，缺设备时持续等待，异常断线后持续重试。
H743 只尝试 CH340/CH340X（1A86:7523/55D4），匹配 `H743_CB_V1.5` 和协议 1 后
读取有效 UID，再进行停止和原有幂等参考初始化；H723 保留先读 IMU1 再随机挑战的规则。
不向 J-Link 或其他 USB 类型发送探测命令。

首次验证的 H743/H723 芯片 UID 写入 Nano `host/device_links.json`，后续重新枚举
串口号但必须匹配已保存 UID；更换板子时需由维护者明确清除该设备的 UID 配对记录。
此文件、巡航参数和辅助轴参数都不在部署脚本的覆盖清单中。
设备长时间缺席也不会放弃重试；多个候选轮流尝试，错误设备不会被发布为有效连接。

网页的“自动连接设备”复选框可暂停/恢复重试，设置会保存并在服务重启后沿用。
手动断开后启用状态下会再次连接；需要持续断开时先取消自动连接再断开设备。
重连只恢复通信，H743 会停止并解除使能，不自动恢复运动、巡航或接线确认。
本地不加启动参数时仍采用手动连接。
