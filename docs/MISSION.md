## 站点、标定和动作

路线仍保存到 `host/navigation.json`，任务配置单独保存到 `host/mission.json`。Web“坐标巡航 → 自动任务”中编辑 JSON 并保存。`legs` 的键是**从 1 开始的第几次到站**，不是站点名称：B 的两次访问可设置不同动作。每个挂起段必须明确配置，空数组表示直接放行；有动作的段必须勾选挂起。

出厂任务为空，不预设抓取、放置角度、二维码颜色含义或标定比例。以下是格式示例，值需要按机械结构实测填写：

```json
{
  "timeout_s": 480,
  "leg_timeout_s": 120,
  "action_timeout_s": 30,
  "vision_max_age_ms": 500,
  "calibration": {
    "verified": false,
    "matrix": [[0, 0], [0, 0]],
    "tolerance_px": 3,
    "stable_frames": 3,
    "max_iterations": 12,
    "max_step": 100,
    "sps": 100,
    "accel": 1000
  },
  "legs": {
    "1": [{"op": "scan", "key": "task"}],
    "2": [{"op": "align", "kind": "block", "target": "red"}],
    "3": [{"op": "align", "kind": "ring", "target": "3"}]
  }
}
```

此示例的 `verified=false` 会拒绝启动含对准动作的任务。确认前必须完成两项实测：

1. 像素偏差到车身前进/左移脉冲的矩阵：`[forward,left] = matrix × [error_dx,error_dy]`。应测出符号、比例和交叉影响，矩阵不得退化。每次仅执行较大的那个分量，完成并确认到达姿态后重新拍摄。
2. 当目标与相机抓取参考点重合时，车辆参考点确实位于配置的站点 XY，航向等于该站到达姿态。相机安装偏移、机械臂工具偏移和机构高度必须一起考虑。识别到某个色块本身不等于获得车辆绝对定位；若目标会移动，或抓取点不对应通道站点，应修改站点/参考标定，不能直接使用 `FIX`。

当前矩阵为整场共享，适用于固定相机/工具几何；不同高度或不同机构姿态需要不同标定时，先固定工作姿态或扩展配置。不得把 `verified` 当成软件自动标定结果。

| 动作 | 字段与含义 |
|---|---|
| `scan` | `key` 保存二维码原始文本，不猜测比赛任务映射 |
| `align` | `kind=block/ring`，`target` 是检测器真实颜色名或数字字符串 |
| `servo` | `channel=1/2, angle, settle_ms`；angle 是主机物理角度，使用现有通道换算；等待时间只是稳定时间，无反馈 |
| `aux` | `axis=5/6, position, sps, accel`；绝对逻辑位置，需事先建立零位和范围；检查 move_id、剩余步数及最终逻辑位置 |
| `wait` | `ms`，非阻塞等待 |

动态目标可写成 `{"op":"align","kind":"block","target":{"scan":"task","index":0,"map":{"1":"red","2":"green","3":"blue"}}}`。`index` 是原始文本字符下标（从 0 开始），包括 `+` 等分隔符。映射为显式配置，示例不代表正式比赛色序。

## 微调协议

所有请求复用 v1 CRC/序号帧；状态中的 leg 从 1 开始，命令的 leg 从 0 开始。

| 命令 | 行为 |
|---|---|
| `NAV ALIGN` | 独立能力探测，返回 `v=2 state path_id leg pending used max=1000 op_id`；HELLO 长度不变 |
| `NAV NUDGE <path_id> <leg0> <FWD/BACK/LEFT/RIGHT> <steps> <sps> <accel>` | 仅当前挂起、已使能、航向新鲜且底盘空闲时接受，返回操作序号 `op_id`；进入 nudging，再调姿回 waiting |
| `NAV FIX <path_id> <leg0>` | 主机断言相机已验证标定位置，固件检查路径、段号、挂起、航向及静止条件后，把车辆参考 XY 设为配置站点；不产生运动 |
| `NAV GO <path_id> <leg0>` | 已经微调但未 FIX、坐标不在站点、已放行、路径/段号不符均拒绝；成功后仍执行配置的到站停留时间 |

每次位置确认前最多 16 次微调、累计 1000 个指令脉冲，单次最多 1000，速度 1～5000 step/s，加速度 1～20000。微调超时 60 秒，IMU 300 ms 过期停车。主机另有动作/路线段/整场超时、串口应答超时和导航状态超时。它们是软件边界，不能代替场地距离与制动实测。

## 视觉输入与 NX 接法

支持重启的生产者应在 sample 中加入 `session_id`（非空字符串，最多 64 字符），每次进程启动重新生成，同一会话内保持不变。`VisionPublisher` 自动生成并附加，无需改相机循环。接收方按 `(source, session_id)` 检查帧号；新会话可从 0 开始，但采集时间仍须严格前进，稳定计数重新累计，已退役会话的迟到帧拒绝。未传 session_id 的旧接口仍按单一 legacy 会话运行，不能在同一任务中直接归零帧号。切换会话不延长动作超时，持续无有效结果仍会安全停车。网络断开重连不会更换现有 publisher 的会话，真正重启/重建 publisher 才更换。

`GET /api/mission/request` 给出 `run_id/request_id/kind/target/station/after`；`POST /api/mission/vision` 的 `sample` 必须包含同一请求身份、`source`、递增 `frame_id`、Unix 秒 `captured_at`、`found`，并带 `error_dx/error_dy` 或二维码 `text`。时间戳必须来自采集时，不能用 HTTP 发送时间；帧必须晚于请求、未过期、身份和目标一致。对准需要同一来源的多个新采样连续落入容差；没找到目标、来源变化或采样间隔过长会清空稳定计数。

`host/mission_vision.py` 提供 `VisionPublisher` 与 `sample_for`，供已有相机进程直接导入，网络在独立线程处理且仅保留最新结果。它不打开相机或串口，也不会把错误颜色或数字改标为目标。

本地提供独立入口 `tools/nx_mission_vision.py`，复用 `nx_vision_live` 的检测器，按请求切换 QR/颜色/圆环数字；数字每帧重新识别，不把预览程序保留的旧识别结果当成新帧。它与预览程序二选一运行，避免重复占用相机。保持现有 NX 视觉环境及模型路径，例如在已部署仓库目录执行：

```sh
MISSION_HOST=http://127.0.0.1:8770 python3 tools/nx_mission_vision.py /path/to/ring_digit_modules --camera 0
```

应使用原视觉环境的 Python，保留原有 `NX_VISION_*` 标定设置。运行此入口还需要现有 tools/nx_vision_live、roi、color、fast、trt 及原模型模块；主机部署脚本只部署 host 层，不替代另一项视觉程序的部署。相机须保持短采集队列，采集时间在读取之前记录，避免把排队旧帧视为新帧。跨主机输入还需同步时钟与控制页 session token；默认同机 loopback 无需抢占浏览器控制权。
