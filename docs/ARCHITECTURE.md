# 架构与实现边界

## v0.2.2 Web 上位机

`host/webserver.py` 提供一个只依赖标准库的 HTTP + SSE 服务，`host/webapp.py` 是它与板卡之间的会话层，`host/static/` 是零构建的前端（一张 HTML、一张 CSS、一个 ES module）。启动方式 `python -m host.webserver`。

**前端不直接碰串口。** 所有字节仍然走原来的 `host/transport.py` 串口工作线程：250 ms 心跳、点动租约、STOP 优先、同编号重试全部保持在原处。`Console` 做三件事：排空工作线程的事件队列并镜像状态、按 1 s STAT / 200 ms 两轴 / 0.5 s SERVO STAT / 0.5 s CHASSIS STAT 轮询、把事件扇出给每个页面。前端只是渲染与发命令。

```text
浏览器 ──SSE /api/events──▶ Session ──┬─▶ Console ──▶ Connection（唯一串口属主）──▶ 板卡
   └──POST /api/command───────────────┘        ▲
                                               └─ 事件队列：reply / connected / error
```

- **控制权是租约不是锁**：第一个打开事件流的页面拿到控制权，其余页面只读。控制页安静超过 6 秒（关掉、崩溃、挂起），`release_stale_control()` 把控制权交给下一个页面。没有这条，一个消失的页面会让服务器余生只有只读页面。
- **写权限只在 HTTP 层收口**：`guard()` 要求会话令牌且必须是控制页，缺令牌返回 400、非控制页返回 409。STOP 同样受此约束，因为"能被别人随手停车"和"能被别人随手开车"一样危险。
- **关闭页面不断串口**：只停止轮询（`Console.tick()` 在没有页面接触的 30 秒后不再发查询），心跳继续由工作线程维持，因此板端租约不会因浏览器关闭而失效。`Ctrl+C` 才发 `STOP` 并关闭串口。
- **推送循环不会静默死掉**：`Session.run()` 捕获每轮异常、写进日志并继续；早期版本因单调时钟从 0 起算而在第一轮就判定"空闲"退出，表现为页面连上但永远不刷新。
- 用 `http.server` + SSE 而不是 WebSocket，是为了不引入任何依赖；板卡命令是低频请求/应答，SSE 的单向推送足够，也避免了 `http.server` 不支持升级握手的问题。
- **主题是 `<html>` 上的一个属性**：两套调色板在同一张表里以 `--变量` 形式各定义一次，组件样式只引用变量，切换主题只改一个属性、不重排任何 DOM。`<head>` 里的同步内联脚本在首次绘制前读 `localStorage` 决定属性，避免闪一下另一套配色。契约测试会比对两套调色板的变量名集合完全一致（少一个就会让对应声明静默失效），并禁止组件样式里出现硬编码色值。默认浅色：这是白天在实验台上看的工具。

## v0.2.4 舵机独立行程

`servo.c/h` 在 **S1/PH9/TIM12_CH2 与 S2/PH6/TIM12_CH1（AF2）**输出两路 50 Hz RC 舵机 PWM。TIM12 挂在 APB1，定时器时钟 200 MHz：`PSC=199` 使一个计数就是 1 µs，`ARR=19999` 得到 20 ms 周期，因此**比较寄存器的值就是脉宽微秒数**，命令与电气输出之间没有任何换算环节。共享一个时基意味着两路同频同相，不需要额外同步。PWM 模式 1 且开启 OCxPE，迟到的写入落在下一个周期边沿，不会截断正在输出的高电平。

TIM12 是通用定时器，没有 BDTR/MOE，比较通道直接驱动引脚；也不需要中断，50 Hz 完全由硬件维持，CPU 占用为零。初始化顺序保证引脚从复位到配置完成一直是低电平：先写 `CCR=0`，再配置 GPIO 复用，最后才置 `CCxE`，然后启动计数器。上电目标：S1 为 90°（1167 µs），S2 为 90°（1500 µs）。

**角度到脉宽使用独立常量表：S1 为 541 项（270°），S2 为 361 项（180°）。** 两表均按半度步进，`pulse[i] = 500 + round(2000*i/channel_steps_max)`，暂定端点为 500 与 2500 µs。`servo_steps_max(channel)` 同时供命令限位及查表使用，逆向状态换算也按通道选表。ARM 测试执行编译后的函数，逐项检查两张表、回读与越界拒绝。修改脉宽或行程配置时要重算对应表。PWM1 模式必须设置 `OCxM=0b0110`；此前只设置 `OCxM_1`（0b0010）的错误已修复，并有寄存器回归检查。

**加一路舵机 = `hw[]` 加一行 + `SERVO_CHANNELS` 加一。** 通道号驱动 `CCR` 下标、`CCMR` 寄存器选择和 `CCxE` 位号，都是按 `h->channel` 算出来的，没有按通道写死的分支；`SERVO STAT` 逐路输出，页面的表盘也按 `data-ch` 逐张渲染。TIM12 只有两路，第三路要换定时器（原分配表把 S3 放在 PE4/TIM15_CH1）。

舵机**不参与 ARM/STOP 语义**：它们是位置输出，必须持续收到脉冲才能保持位置，所以既不受使能门控，也不会被急停切断。命令分发里它们只写入协议第 4 组共用变量 `a/b`，与运动命令互不影响。

## v0.2.1 双串口

`serial.c` 同时启用 USART1（PA9 TX / PA10 RX）与 UART7（PA15 TX / PA8 RX，AF11），115200、8N1。IRQ 各写独立环形缓冲，comm 任务每轮每路最多取 256 字节，分别组帧；完整请求进入同一分发器和去重缓存。所有应答双发，发送进度与 10 ms 无进展超时按端口独立维护。串口统计是两路合计。两路服务于同一控制会话，任一路 PING 都续租，不能当作两个互相隔离的控制器；见 [接线及使用边界](WIRELESS.md)。

## v0.2 底盘层

新增 `chassis.c/h`，定义绿色 PCB 朝前、M1/M2/M3/M4 对应左前/右前/左后/右后。提供六种基础动作、等步数四轮同时启动、RAM 方向校准、状态反馈和独立点动租约；GUI 新增 `chassis_panel.py`，串口线程以最新意图代替点动 FIFO。详细行为见 [CHASSIS.md](CHASSIS.md)。本页下方的独立通道说明仍适用于原始 MOVE/WHEELS 接口；底盘原语使用公共首比较值，同一临界区更新四轮速度。

## 数据路径

```text
Python Tk GUI --线程队列--> 串口工作线程 --CH340/115200--> USART1 RX 中断
                                                        ↓ 环形缓冲
                                                   comm 任务 / 协议
                                                        ↓ 短临界区
motion 任务 / 1 ms 加减速 --> 七轴状态 --> TIM8/TIM5 比较中断 --> STEP/DIR
supervisor 任务 / 10 ms --> 心跳超时停止
```

摄像头在上位机侧，不经过 STM32。无 HAL、无 Cube 生成文件；CMSIS 提供寄存器声明、内核操作和启动支持。

## FreeRTOS 调度

FreeRTOS V11.2.0，ARM Compiler 5 的 RVDS ARM_CM4F 端口用于该 Cortex-M7（非 r0p0/r0p1）；该端口明确检查不适用的早期 M7 修订。硬件 FPU 上下文切换已开启。

| 任务 | 优先级 | 栈 | 工作 |
|---|---:|---:|---|
| supervisor | 4 | 2048 B | 每 10 ms 检查心跳租约 |
| motion | 3 | 2048 B | 每 1 ms 更新速度与有限行程制动包络 |
| comm | 2 | 6144 B | 解帧、应答、命令处理；单次接收处理有字节预算 |
| idle | 0 | 1024 B | 内核空闲任务 |

TIM8_CC/TIM5 中断优先级 4，USART1/UART7 优先级 6，SysTick/PendSV 优先级 15；FreeRTOS 最大系统调用中断优先级 5。定时器中断不调用 RTOS API，高于内核 BASEPRI 屏蔽门限；跨任务/定时器共享状态使用短小的 PRIMASK 临界区。临界区真实耗时仍需示波器或 DWT 实测。

程序与常量放内部 Flash；数据、MSP 和 RTOS 堆放 128 KiB DTCM。I-cache 开启，D-cache 暂不开启；本版无 DMA。后续 DMA 缓冲不能沿用 DTCM，需要另分配可达 SRAM，并制定缓存一致性策略。

## 步进脉冲实现

保持原引脚，TIM8 四通道和 TIM5 三通道使用输出比较翻转。两个计数器均设 50 kHz、ARR=65535，共用一种模块回绕算法。计数步长 20 us，1 step/s 的半周期为 25000 个计数，因此可以用有符号 16 位模差判断下个比较时刻是否仍在未来。

半周期为 `50000/(2*sps)`，余数累加分配到相邻计数间隔，恒速时平均频率正确；边沿间隔具有小于 20 us 的量化误差。最高 5000 step/s 时半周期 100 us，3000 step/s 时约 166.7 us。这里优先选择简单、可验证的全速段实现，不宣称达到微秒以下脉冲抖动。

七轴同时达到配置上限时，比较事件总量上限约为 `2*(4*5000+3*3000)=58000 次/秒`，共享向量可合并处理同时事件。硬件自动翻转引脚，中断更新下一次 CCR。CCR 基于上一次计划值推进；迟到到无法及时更新时锁存故障，停止全部输出，避免静默等到下次回绕。

起始方向建立时间至少 200 us。仅上升沿计步；有限行程在最后一个下降沿完成。输出初始强制低电平，ARM 本身不会发脉冲。STOP 不截断正常的最后一个高电平；硬故障路径会立即强制低电平。

速度更新采用 milli-step/s 累加，周期 1 ms；有限行程用整数平方根限制到 `sqrt(2*a*remaining)` 的制动包络，最后由中断保证脉冲数量。初始速度为最多 10 step/s，最后若干步可能有离散化变化；尚未实现 S 曲线、跨轴直线插补或严格同步到达。只有实机验证后才能确定驱动器/负载能否跟随。

`WHEELS` 在一个临界区内提交四轮目标，四轮计时共用 TIM8。但每个通道保持自己的相位，第一版不保证四轮首个边沿完全同一计数值。麦轮连续速度控制通常不要求首脉冲同相。

## 引脚资料修正

原 `PIN_ALLOCATION.md` 保留原样；以下内容优先以硬件手册/本实现为准：

- 通道独立不等于普通 PWM 频率独立，因此这里使用输出比较调度。
- TIM8 与 TIM12/13/14 的部分向量共享；本实现使用 TIM8_CC 与 TIM12_CH1/CH2。TIM12 只做 PWM，不用任何中断，共享的 break/update/trigger 向量都不涉及。
- PC2 已作为 M5 DIR，不能再标为可用 ADC。
- PH6、PH9–PH12、PI2、PI4–PI7 等与显示屏接口复用；本工程不初始化、不连接该显示模块。
- 红色 LED 为电源常亮，不是第三个可控 GPIO。
- v0.2.1 将 PA8/PA15 从第三路超声波预留改为无线 UART7，后续不得重复分配。
- v0.2.2 启用 PH6（TIM12_CH1）与 PH9（TIM12_CH2）作为 S1/S2 舵机，v0.2.13 按 PCB 接口线对调为 S1/PH9、S2/PH6；S3（PE4/TIM15_CH1）仍未启用。

## 尚待接硬件完善

- 四轮物理位置、轮径、减速比、细分、方向：用于底盘 `vx/vy/wz` 变换。
- 电机驱动器型号：用于确认 3.3 V 兼容、脉冲有效边沿、DIR/STEP 时序、ENA/FAULT。
- 限位、回零、编码器及独立急停电路：本版没有对应引脚或驱动。
- 舵机型号：确认实际满行程脉宽是否就是 500–2500 µs；若不是，改常量并重算脉宽表。
- 超声波、IMU 型号：当前不驱动这些外设，不返回虚构数据。
- 传感器任务、订阅上报和参数保存可以沿当前协议分层扩展；此版本通过查询响应上报。
