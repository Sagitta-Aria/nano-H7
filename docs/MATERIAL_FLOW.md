## 执行顺序

1. 启动前车在 O 点，转盘为空，M5停在已建立参考零点的最高位置。自动连接、恢复参数后，在未使能状态设置 `LIFT DIR -1`（M5负方向下降），执行 `AUX ZERO 6`，以M6当时的静止位置作为本次运行的零点，不进行机械寻零。每次点击全流程启动只设置一次M6零点，途中抓放不重新定义零点；M5保留已有参考，下降深度参数仍为正数。恢复行程范围并检查零位与全部抓放目标后，建立 O 点并使能；任一步失败均中止启动。
2. 到 A 后用摄像头2连续三帧锁定四组任务码。未识别时沿用有界前后搜索；锁码后立即关闭摄像头2并打开摄像头1，启动等待不设超时。确认相机1就绪后，搜索有偏移时先物理返回A，再驶向B。相机1跨两轮B/C/D持续开启，最终回O后由后台关闭。
3. 到 B 完成已配置调姿，挂起巡航、开启位移积分，复用A点已打开的摄像头1。若到站确认后又进入航向修正，`NAV_HANDOFF_NOT_READY` 触发同路径、同段、IMU与执行器静止状态重查，60秒内等待恢复交接；其他故障仍中止。按本批抓取码逐件张爪、下降到B点高度，在识别框内连续3个新鲜帧确认目标色后，等待识别后抓取延迟（默认2秒，可在B点参数调整），再夹取、提升并入盘；识别和延迟期间底盘保持停止。S1为夹爪；S2为转盘，依次存入第1/2/3槽，即270°/135°/0°。每件入盘后M5保持最高点0、M6回0、夹爪打开，再下降等待下一件。B点颜色、首帧和断帧等待无总时限，也不消耗站点或整场任务时间预算；断帧后须重新确认连续3帧。相机明确错误、通信异常和机构运动超时仍中止。识别框参数及边界见 [B点取料](B_PICKUP.md)。
4. 三件抓取结束后，按已累计的视觉位移物理回到 B 的通道坐标，再恢复剩余路线。不会把偏移后的车位直接当作 B。
5. 到 C 完成调姿，用现有圆列识别摆正并视觉校准到点1。按**第3槽0° → 第2槽135° → 第1槽270°**取料。放置码第N位对应本批第N件抓取物料，反向取出时目标点也同步反序；例如 `156+231` 的实际放置顺序为浅蓝→点1、黑→点3、红→点2。两批及C/D均沿用同一物料目标映射。
6. C 全部放完后按地面 **1 → 2 → 3** 抓回，放回每件原来的转盘槽位。重新抓取使用 `place_drop_down` 作为地面抓取高度；其他动作仍使用已保存的抓放参数。这使 D 的物料身份与二维码映射保持一致。
7. 首次到 D 完成调姿、圆列/点1校准，再按同样槽位顺序和任务码放置；每件成功完成后记住该点的第一层颜色，D 不收回。
8. 返回 B，用第二批抓取/放置码执行 B/C，第二次D按下述叠放流程执行，最终回 O。两轮共24次单件机构动作：B抓6、C放6并抓回6、D放6。

## 第二次D点叠放（已部署）

在「升降与旋转 → 抓取与放置 → 放置位置」设置 `d_second_drop_down`（第二次D点放料下降）。这是从M5零点起算的绝对下降脉冲，数值越小，放料位置越高；必须≥0且小于地面放料 `place_drop_down`。默认-1表示未标定，全流程在启动前拒绝该值。旧参数文件加载时仅在内存补此字段，保留原校准值和磁盘内容；保存仍使用原抓放配置接口。

首次D点每件成功放置并返回机构原点后，才在本轮 `task.d_layout` 中记住“点号→物料颜色”。每次启动新任务清空，不读取上次运行的旧布局。第二次D点必须有完整三点布局，两次到站朝向差须≤10°，防止前后顺序反转。

第二次D关闭数字OCR：先用同一帧中的两个圆环中心连线摆正；然后观察单个或两个圆环，以第一层颜色推断点号。单圆颜色必须能唯一定位；重色可由双圆的前后颜色顺序消除歧义。全部同色、布局不匹配或视野不足无法消歧时，在有限±X范围搜索后停车。黑色色块判定只看圆环内部缩小区域，排除黑色环边。

连续三帧确认同一点后，对准该点的**圆环中心**，色块顶面仅提供身份。如果该点不是2，按整场锁定的 `material_flow.json` 点距移动到2，再用新鲜视觉重新确认点2并微调圆心。无需同时识别三个圆。点距不新增副本或独立调参入口，第二次D与前面C/D使用同一快照。随后仍按第二批二维码的目标点放置，仅本次D放料下降切换至 `d_second_drop_down`；B、C、首次D以及普通单件测试保持各自原方案。

未改变MCU协议；新增相机算法在 `host/stack_ring.py`，仍由现有相机控制器检查帧时效、有限移动编号、剩余脉冲和静止状态。运动中STOP立即取消后续放置。已完成本地与NX隔离测试及线上只读页面验收；仍需现场标定叠放高度、颜色阈值并确认第一层放好后圆环仍可见，尚未执行实车叠放。

## 控制与接口

- `POST /api/competition/start`，请求 `{"full_flow":true}`，使用现有控制页身份。省略该字段仍执行历史的已保存路线模式。
- 状态在现有 `/api/state` / SSE 的 `task.material`、`task.tray`、`competition` 中；显示批次、站点、物料、槽位及目标点。
- 每次有限底盘运动必须收到同一 `move_id`、静止、`remaining=0` 才可抓放；每次抓放必须收到同一 `job_id` 的完成状态，并核对M5/M6回原点才可继续移动。
- 停止自动任务或全局STOP会取消相机控制、机构动作与剩余路线，不自动恢复，也不在故障时张开夹爪。任务运行中不能手动抢占或改抓放参数。
- 复用现有H743协议，无新增固件命令。入口在 `host/competition.py`，全流程编排在 `host/material_flow.py`，通过 `host/mission.py` 交接相机、抓放和巡航。
