# NX 规划、动作编排与 H743 逐步执行

## v0.2.29：X 点出发

坐标巡航可选择 O 或 X 起点。X 固定为 `(0, 28800)`、地图朝向 `-180°`，第一段必须前往 A。Web 可通过“添加 X 点”补充站点；已有 X 时直接选择。添加时仅在必要时将通道上边界扩至 28800，原站点坐标和路线保持原值。`start_station` 保存起点下标，旧文件缺省为 0（O），保存/切换选择本身不建系、不运动。

将车实际放在 X 并对准 -180°，解除使能后点击“当前位置设为 X”，再使能、开始巡航。X 的首段强制使用保存的 `turn_inset_steps` 向场地几何中心内移，即使普通“转前内移”开关关闭也执行；查询确认完成后转到地图 0°，再次确认完成后，保持 0° 从内移位置直接平移到 A，**不返回 X 或原通道**。到 A 的调姿、停留、任务和后续路线沿用 O 出发的规则。地图预览显示这段内移及直接到 A 的向量。停止会取消未执行动作，内移途中停止后不自动续走。

X 建系要求 H743 v0.2.29，在 `INFO` 中提供 `nav_reference=1`。扩展 `NAV RESET <ox> <oy> <x> <y> <heading_cd>` 将地图原点保持在 O，同时记录当前实际坐标和出发姿态；首次 START 使用新鲜 IMU 航向与声明姿态的差建立地图朝向，后续 STOP/START 保留此坐标系。原 `NAV RESET <ox> <oy>` 仍代表 O、0°。比赛一键准备和 Tk 编辑器也使用已保存的起点，全流程最终仍返回 O。

本地验证：Keil ARM Compiler 5 编译、`tests.test_x_navigation` 的实际 ARM 镜像/模拟串口用例，以及 `python -m tests.x_navigation_browser` 的隔离 SIM 网页检查。验证记录见 [X 起点验证](validation_x_navigation_20261021.json)。本次未部署 NX、未烧录或运行实车。

v0.2.26：行驶航向偏差超过 5°会自动恢复航向并继续当前目标，不再报 `heading_deviation` 终止；固定三次终点修正次数限制取消。比赛入口和参数保存见 [比赛启动](COMPETITION.md)。下文保留各历史版本的说明。

v0.2.22 将巡航动作决策移到 NX：路线拐弯、每次到点是否调姿、转前内移与回位由 NX 逐步下发。H743 提供通用转向、平移、到站、离站和结束动作，负责航向闭环、脉冲执行与停车保护。新 Web/Tk 使用 `NAV START <id> HOST`；旧 `NAV START` 保留兼容执行方式，不用于新上位机。

2026-10-16 巡航回归修正：重新 START 时，NX 读取 `heading_cd` 实测地图航向作为首个动作的身体朝向，不能使用上次未完成转向的 `target_cd`。有限向量平移的四轮起步速度、加速度按轮脉冲比例分配，避免任意角度回位在加减速时偏离方向；原有每轴 0.51 脉冲完成阈值、最多三次修正和超时保护保持不变。

到站 ACK 不等于视觉任务可以接管。必须等巡航执行器通过后续查询确认当前路径、当前段已到站，再允许站点动作；普通 `NAV STAT` 提前看到挂起不会越过这个确认。若这之后板端恢复到站航向修正，物料任务的 `NAV SUSPEND` 可返回 `NAV_HANDOFF_NOT_READY`；上位机重查同路径、同段、IMU有效、无故障、到站挂起和同执行器静止状态后再申请交接，轮询至少间隔100ms，60秒仍未就绪则中止。路径变化、使能丢失和其他错误不会被此重试吞掉。最后一站若为圆列视觉任务，验证 `NAV RESTORE` 后的停止状态及路径编号后，同时结束任务和 NX 巡航控制权；界面同步解除占用。该分支在退出位置结束，不再启动空路线或自动返回站点。

v0.2.20 增加 [自动任务与相机校准](MISSION.md)：相机辅助到达指定地点并确认车辆参考位置，完成动作后继续下一站，不倒走回溯。巡航站点必须与视觉校准后的车辆位置一致。

## v0.2.19：站点与路线分开

原来路线写死在固件里（`route[] = {1,2,3,4,1}`，即 O→A→B→C→D→A，五次到点），站点数也固定为五。现在两者分开：

- **站点表**：2～32 个，每个带名字、坐标和到达姿态，编辑一次。
- **路线表**：1～32 段，每段是一个站点下标加一个挂起位。同一站点可以在路线里出现任意多次。

所以 `O A B C D B C D A O` 这样九段、B/C/D 各到两次的路线可以直接表达。站点提供默认的到点调姿开关和角度，路线段可单独覆盖；同一点两次到达可以分别不调姿或调到不同角度。挂起位同样属于段（第一次到 B 要抓取，第二次可能只是路过）。

**站点名只存在上位机**。板端回报 `station=<下标>`，由上位机映射成名字，这样板子不会和上位机的命名不一致，也不用在固件里存 32 个字符串。

带挂起位的段到点后不走停留计时，而是等上位机发 `NAV GO <path_id> <leg>`。这是给视觉用的：到点、看一眼、对准、抓取，完成后再放行。放行命令必须指明腿号，上一站点迟到的放行不会启动下一段。挂起期间姿态仍然维持，放行后停留计时重新开始。

横移里程计同期补上，细节见 [协议](PROTOCOL.md)。原来的位姿模型只有一个自由度（标量距离投影到航向），横移算出来恒为零；现在按正交基分解出前进和左移两个分量。横移标定系数暂定 1.0，**实际值必须现场实测**。

旧的 `navigation.json`（`points`/`headings` 加写死五段）加载时转换成站点表加相同的五段路线，保留坐标、角度及运动参数。旧配置未明确提供的到点调姿开关一律关闭，不因已有 0°或其他角度自动启用；保存时写入新格式。


0.2.17 每段直线自动加入[陀螺仪辅助纠偏](STRAIGHT.md)，按地图目标航向实时调整轮速，使用共享 P/角度容差。计程改为四轮合成平移脉冲，保留田字格路线与转向/调姿/停留流程。

0.2.10 新增独立[闭环转角](TURN.md)，可在“底盘运动”页使用；无需启动巡航。

坐标单位仍是轮脉冲，不是毫米。建立 O 后，第一次 H743 接受 `NAV START` 时，用刚收到的有效 H723 航向建立地图朝向；这个方向定义为 +Y、0°。停止后重新 START 保留地图朝向与 XY，直到重新建立 O；不再随车头方向旋转整张地图。角度顺时针为正，+X 为 90°，−Y 为 180°，−X 为 −90°，180° 与 −180° 等价。H723 水平安装约定沿用 X 向前、Y 向左、Z 向上，因此上位机将 BMI088 的逆时针 Yaw 取负后转发。

默认点和 O→A→B→C→D→A 顺序保留。站点的 `heading` 与 `arrival_enabled` 保存在 `host/navigation.json` 的 `stations` 中，角度单位为度，范围 −180～180，支持两位小数；O 的角度固定 0。所有站点默认不调姿，保留入站方向。路线段可指定 `arrival_enabled` 和 `heading`，分别覆盖站点设置；启用并填 0°表示调到地图 0°，关闭表示不调姿。

## 开发职责与恢复原则

后续开发以 NX 为决策层：负责寻路、任务编排、转向位置选择、视觉策略与恢复决策；H7 负责通用运动执行、实时航向闭环、轮速/加减速、STEP 输出和必要保护。优先自动化与鲁棒性，可恢复的小偏差应由 NX 自动纠正或重规划并报告警告，不增加与任务执行无关的停车条件。恢复必须基于仍有效的位置、航向和动作反馈，不能把未完成的动作直接当作成功。此次中心优先寻路没有新增自动故障恢复流程，也未改变现有停止阈值。

## 田字格地图与寻路

Web 的“场地范围与通道”可直接输入左/下边界、宽、高和中间通道距边界的距离，单位仍为整数轮脉冲。修改后直接“保存参数”，不再显示草稿图，也无需先应用草稿。默认保留站点绝对坐标；需要随场地缩放时勾选“同步调整站点”。站点暂时不在通道线上也可保存、重新加载，方便分步修改；建立起点及启动巡航前再检查通道、站点和 X 出发约束，不合格时不下发运动。中间通道必须严格位于两边界之间，绝对坐标仍受 ±1000000 限制。“直接编辑六条通道的绝对坐标”保留原输入方式。

勾选“同步调整站点”后，原来在线上的站点映射到对应新通道；位于两个相邻通道之间的坐标按该区间比例取整。站点名、到达姿态、路线访问次序及挂起标记保持原值。未勾选时保留原站点坐标，越界或离开通道的站点可以先保存，执行巡航前须修正。范围/站点变化只改变配置，车辆不会移动；实车参考点应与新配置核对并重新建立所选起点。显示宽高按两边界之差计算，负坐标场地也适用；毫米换算仍是显示用途。

三条竖线与三条横线的坐标分别保存在 `grid.x`、`grid.y`，默认均为 `[0,14000,28000]`，可在 Web/Tk 编辑。每组必须是 −1000000～1000000 范围内的三个严格递增整数。旧 JSON 自动补充默认田字格；自定义旧点若不在默认通道线上，必须修改通道参数或点坐标后再使用。

这六条线表示通道中心线。只有外圈及中间十字通道可以连接，四块格子内部不允许穿过。O/A/B/C/D 可以在交点，也可以在通道线中间，但必须在外圈范围内。修改任务点不会自动生成新的通道线。

NX/PC 后台使用九个交点、当前位置与目标点组成最多 11 个节点的图，通过 Dijkstra 搜索最短通道距离，再拼接配置的所有路线段。搜索保留进入节点的横/纵方向：先比较距离，等长时依次选择中心以外转向更少、总转向更少、位移段数更少的路线；最终相同时按固定状态顺序选择。中心指中间通道交点 `(grid.x[1], grid.y[1])`，不一定是场地几何中点。Web 预览及模拟板采用相同规则。直线可达不绕中心；O 本身是目标时仍正常到达。

H743 不运行寻路算法，校验收到的完整路线，并执行 NX 之后下发的单步动作。路线边只能连接同一横线或竖线上的点；同一通道中的多个共线交点可以直接经过。通道之间间距可以不等，支持负坐标。转前内移是独立的局部平移，不属于田字格寻路捷径。

开始前后台主动查询一次 NAV STAT，以新回复中的整数 XY 为起点，检查全部任务点和当前估算位置；不在线上则在上传前报告规划失败。H743 在 BEGIN、COMMIT 和 START 再次检查起点与通道约束。当前位置只按整数脉冲取整，不自动吸附到附近通道。中途停止产生横向累计偏差时也可能拒绝重新开始，应重新定位，不能通过假设吸附来掩盖误差。

默认 A→B 为 `(0,14000)→(14000,14000)→(14000,0)`，在中心转向，不再经过 O；B→C 沿中间竖线直行；C→D 为 `(14000,28000)→(14000,14000)→(28000,14000)`。临时经过中心或其他站点坐标不算任务点到达，不触发该点姿态或停留。关闭 B 到点调姿时，入站航向随新路径变为 180°；视觉任务需要固定方向时应启用该次到点调姿。

这是通道中心线规划，尚无车身轮廓膨胀、禁行矩形尺寸、转弯扫掠检查、障碍地图或动态绕障。实际场地的中心线、脉冲/毫米比例、车身转向余量和定位误差都需实测，不能仅凭田字格路线保证整车不越界。

## 每一段的执行

可选“转向前向场地中心内移”：Web/Tk 默认距离 1000 脉冲。NX 只在明确计划的路线转向或启用的到点调姿前执行“向中心平移 → 最短角差转向 → 回到原通道/站点”；未启用到点调姿的站点不会因为默认角度为 0°而内移。H743 只执行 NX 下发的单步 `NAV EXEC`，不再自动决定站点姿态或场地中心内移。

回位用于保留原通道路线和视觉站点位置。全过程计入 XY，完成实际回位后才消除轮脉冲取整的小量残差；较大误差最多修正三次，失败报错。中途停止保留已移动坐标，若偏离通道需重新定位后启动。

距离可设 1～100000 整数脉冲，按平移中脉冲最多的轮子计，斜向时地图 X/Y 分量不等于该数值。中心附近自动缩短，中心位置或航向已在容差内跳过；独立手动转角、停留期间抗漂移修正和视觉微调后的航向恢复不额外内移。内移/回位保持车头方向，偏航超过 5°停止；整次内移、转向、回位共用 60 秒超时，低轮速或过大距离可能超时。

NX 在回位后显式下发普通原地纠偏，重新确认新鲜航向样本稳定后才继续，不重复内移、不重置该次内移流程的 60 秒超时。旧版专用内移状态机及 `inset_return_heading` 判定已移除；平移期间偏航超过 5°仍报 `heading_deviation`。`NAV INSET` 仅保留关闭状态的兼容查询，不能再启用板端内移。

途经中间通道交点的转向由 NX 直接下发原地转向，不再做内移/回位，即使中间通道不在场地几何中点也是如此。到达任务点后的指定姿态调整仍遵循原有内移/回位规则。离站时仍先朝向下一条通道再前进，尚未改成保持车头横移到中心；不直接删除边界处的回位动作，以免从通道外接出一条斜线。

该功能在拐点附近临时离开通道中心线，不改变全局田字格寻路。1000 脉冲是初始可调值，避线效果仍受车身尺寸、横移打滑和场地布局影响，需上车验证。

1. NX 从完整路线取当前段的下一交点或最终目标。通道前进小段只改变 X 或 Y，行驶航向为 0°、90°、180°、−90°。
2. NX 比较前后两个计划朝向，决定是否内移。计划朝向相同时只确认/纠偏；中心交点的途经转向直接原地完成；其他位置存在实际计划转向且开启内移时，依次执行内移、最短角差转向、回位和普通纠偏。每步 ACK 后仍须轮询完成，才下发下一步。
3. H743 转向结束必须先完成所有 STEP 高脉冲，再通过连续三个新航向采样确认误差不超过容差，不追加固定 300 ms 停留，相邻确认采样间隔不超过 200 ms。同一采样重复读取不能完成确认。
4. NX 下发地图目标 XY 和保持航向，H743 换算轮脉冲并进行航向纠偏。旋转不计 XY 平移，内移、回位和通道前进均计入坐标；偏航超过 5°停车。每步完成后停在 checkpoint，等待 NX 下一个动作。
5. 到达任务站点后，NX 根据该次访问的开关决定是否调姿，再确认到站。关闭调姿时保持入站方向；不因默认角度为 0°而转向或内移。相邻站点重合时跳过平移，仍按该次设置处理调姿、挂起和停留。
6. 挂起需明确放行，完整停留后由 NX 下发离站并执行下一段；最后一段结束后完成任务，不循环。停留期间的小角度抗漂移由 H743 闭环处理，不额外内移。

到达姿态与入站方向独立，仍可设置任意 −180～180° 的姿态。例如沿 +X/90° 到达 N，N 的姿态设置 −90°，则到 N 后再原地转向 −90°。禁止斜线前进不代表禁止原地经过斜角姿态。

## 操作

H743 固件需更新至 `firmware/build/robot_h743.hex`（0.2.22，NX 逐步执行接口），握手显示 `fw=0.2.22 nav_heading=1 nav_grid=1 nav_path=1`。Web/Tk 启动前额外探测 `NAV EXEC v=1`，缺失则中止上传。本次固件修改用于提供通用动作接口并移除旧内移状态机；站点行为和内移参数由 NX 配置，之后调整这些配置无需重新编译固件。本次只生成固件，不烧录或运行实车运动。

连接 H723，等待身份握手及静止校准完成。将 H723 刚性安装在车体上并保持水平，车头对应其 +X；车辆放在 O，解除使能后点击“当前位置设为 O”。在 Web/Tk 的坐标巡航页编辑通道、站点、到点调姿开关与角度、内移、速度、加速度及停留时间，保存后使能并开始。上位机先查询最新坐标，再规划整条路线，逐条确认站点、路线段、通道及运动参数，再执行 BEGIN/WP/COMMIT 上传，最后发送带路径编号的 START HOST。NX 后台持续推进动作和停留，不依赖浏览器保持打开；H743 负责当前动作的执行与保护。

“停止巡航”只停止 M1～M4；辅助轴保持独立。“停止全部”解除使能并停止全部轴。新 START 从保留位置重新前往 A，不是继续当前任务点，地图朝向保持首次 START 时的定义。改变 O 标签、手动轮命令、DIR 校准、搬车后须重新建立 O。

H723 重连、USB 会话变化、采样时钟回退会使旧航向基准失效，当前巡航停止，要求重新建立 O。真实巡航需要上位机持续在线转发 H723 数据；当前没有 H723→H743 的直接硬件通信链路。

## 航向桥接与停止条件

串口工作线程在发送前读取最新有效样本，约 20 Hz 转发，绕过普通命令队列；只转发握手后、已校准、无传感器错误、收到不超过 150 ms 的数据。重复样本不会刷新 H743 的航向期限，航向命令不自动重发。每个 H743 连接使用独立会话标识，H723 连接变化或时钟回退会更新标识。

H743 对所有活动阶段执行 300 ms 航向超时，包括转向、前进、到点调姿和停留。数据失效、会话变化或单次转向超过 60 秒均停止巡航；恢复数据不会自动续跑。转向采用与独立转角共享的可调 P，默认 20 (step/s)/°；误差超过容差且 P>0 时，最低目标轮速默认 200 step/s（`TURN_MIN_SPS`），可通过界面或三参数 `TURN CONFIG` 调整为 1～5000，最高仍受用户设置的最高轮速限制，直线纠偏不套用基础转速。通过“应用陀螺仪参数”调整非负 P（0.2.18起无调参上限，0关闭纠偏），板端返回确认；完成容差默认 ±0.2°、可调 0.01～10°，与独立转角共用，实车仍需检查减速、惯性及陀螺仪误差。

## 协议

所有命令仍使用原 v1 序号及 CRC 帧。角度协议字段为整数百分之一度（centidegrees），界面/JSON 则使用度。

```text
NAV RESET 0 0
NAV STATIONS 5
NAV POINT 0 0 0
NAV POINT 1 0 14000
NAV POINT 2 14000 0
NAV POINT 3 14000 28000
NAV POINT 4 28000 14000
NAV GRID X 0 14000 28000
NAV GRID Y 0 14000 28000
NAV ATTITUDE 0 0
NAV ATTITUDE 1 9000
NAV ATTITUDE 2 -9000
NAV ATTITUDE 3 18000
NAV ATTITUDE 4 4500
NAV LEGS 5
NAV LEG 0 1 0
NAV LEG 1 2 0
NAV LEG 2 3 0
NAV LEG 3 4 0
NAV LEG 4 1 0
NAV CONFIG 500 2000 3000
NAV IMU -1234 1 12345
NAV BEGIN 123 7 0 0
NAV WP 123 0 0 14000 0
NAV WP 123 1 0 0 1
NAV WP 123 2 14000 0 1
NAV WP 123 3 14000 28000 2
NAV WP 123 4 14000 14000 3
NAV WP 123 5 28000 14000 3
NAV WP 123 6 0 14000 4
NAV COMMIT 123 CHECKSUM_DECIMAL
NAV START 123 HOST
NAV EXEC
NAV EXEC 123 1 0 0 0 0 500 2000
NAV EXEC
NAV STAT
NAV STOP
```

`NAV IMU <绝对顺时针角_cd> <有效0/1> <会话1..2147483647>` 是上位机桥接入口，H743 在建立 O 后首次 START 时记录其绝对角作为 0°；不要拿旧日志或手填角代替实车反馈。`NAV ATTITUDE <站点下标> <角_cd>` 保留兼容站点角度；HOST 模式按 EXEC 下发的角度执行。`NAV GRID <X|Y> <低> <中> <高>` 配置一组通道，成功返回 `OK cmd=NAV_GRID`，顺序无效或活动期间修改返回 `ERR code=NAV_GRID_INVALID_OR_BUSY`。POINT/GRID/ATTITUDE/CONFIG 在巡航活动期间拒绝修改。

START 要求坐标已建立、全部站点已上传、完整路线已提交且未消费、四轮空闲、输出使能、航向新鲜、上传起点和 H723 会话仍匹配。STAT 状态包括 `idle/turning/moving/orienting/waiting/done/stopped/blocked/fault/nudging/suspended/checkpoint`，包含 `heading_cd`（相对出发航向）、`target_cd`、`arrival_cd`、`imu`（航向新鲜）、`fault`；HOST 模式的 arrival_cd 是 NX 为该次访问确定的保持航向。

STAT 中 `planner=host_grid` 标识 Nano 规划、H743 执行，`wx/wy` 为下一小段端点，`segment/segments` 为当前任务腿的小段编号与总数。`target/tx/ty/leg` 始终描述 A/B/C/D 任务目标，不会被临时拐点覆盖。零距离任务的 segments 为 0。`path_id` 为路线编号，`route_ready=1` 表示已校验且尚未启动；启动会消费该提交。STOP 后必须重新规划和上传。`grid_segment` 表示内部小段出现两轴变化或零长度，停止而不是走斜线。

### 完整路径上传事务

- `NAV BEGIN <path_id> <count> <start_x> <start_y>`：新建临时上传，编号 1～2147483647，端点数从配置的路线段数到 64；包含每次任务到达，重合点也须保留。要求坐标有效且四轮空闲，起点必须与板端最新取整坐标一致。
- `NAV WP <path_id> <index> <x> <y> <leg>`：端点按 index=0 开始连续上传；leg 是从 0 开始的路线段号。每条使用协议原有 CRC 和同序号重试，重复帧不会重复插入。
- `NAV COMMIT <path_id> <crc16_decimal>`：CRC16-CCITT-FALSE，初值 0xFFFF，对所有规范 ASCII 行 `index x y leg\n` 连续计算，换行为 LF。Python `path_checksum()` 给出计算；上面 CHECKSUM_DECIMAL 必须替换为实际值。
- COMMIT 同时验证所有点在有界通道上、相邻边沿实际通道、全部路线段顺序及最终目标齐全。仅零距离任务到达可重复位置；中间拐点不能为零长度。通过才发布完整路线，COMMIT 不移动。
- `NAV START <path_id> HOST`：编号必须匹配已提交路线，保留原启动保护，随后停在 checkpoint。NX 用通用 `NAV EXEC` 单步推进，字段及完成判据见 [协议](PROTOCOL.md)。旧 `NAV START <path_id>`/裸 START 保留兼容行为，也只能消费已提交路线，绝无板端寻路回退。

独立上传暂存区与执行区各 64 条记录，任务只从执行区读。NAV STOP/STOP/CHASSIS HALT/ARM 0、RESET、参数修改、手动底盘运动/校准、H723 会话变化都会作废暂存与未消费路线。上传相邻有效数据的间隔不得达到 5 秒；超时清空，不会自动继续。错误 ACK 或主机队列满会取消后续发送，START 不会跟随失败上传。串口线程继续优先 STOP，并在上传期间发送 PING 与新 IMU 采样。


超声波 `navigation_obstacle()` / `NAV OBSTACLE` 仍只停止和保留目标；清除障碍不会自动继续，`NAV REPLAN` 仍返回未实现。

## 验证范围与实车检查

工具链为 Keil ARM Compiler 5，目标 STM32H743 Cortex-M7。本地重新生成 AXF/HEX/BIN，使用 Unicorn 执行实际 ARM 固件检验方向、前进脉冲、到达姿态、稳定确认、超时、停止和辅助轴独立性；模拟板使用明确的合成航向，不能当作实物陀螺仪证据。

位置仍是开环脉冲估算，每个小段完成时报告命令端点；没有编码器或外部定位验证实际到点。首次实车验证应检查正转/反转与 IMU 符号、90°/−90°/180° 转向、对准前不前进、拐点停车与转向、仅在任务点停留、拔掉 H723 后停止，以及低速小距离的完整路线。车辆惯性、打滑、安装误差和 BMI088 无磁参考的长期漂移需要实测。

本次回归包含实际 ARM 固件中的正交小段、通道中间起终点、离网目标拒绝、固定地图朝向、航向安全与任务停留；纯规划器使用逐脉冲 BFS 校验不等间距网络内所有点对的最短距离。网页和 Tk 使用模拟板验证完整路线与参数编辑。模拟结果不代表实车精度。
