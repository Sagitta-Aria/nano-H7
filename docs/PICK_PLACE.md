## 初始状态与操作

- 点击“一键测试抓取”或“一键测试放置”即可：自动保存当前动作参数，读取机构状态，应用上方已保存的 M5/M6 范围，然后自动使能并执行一次流程。不再要求分别点击保存、应用范围、使能。调试页另有“一键测试B点完整抓取”，仅读取 B 点专用机构参数并直接执行一件抓取入盘动作；通用参数表中的未保存草稿不会影响 B 点测试。
- 测试按钮不等待相机或外部视觉回调，也不平移、转向底盘；使用操作者已标定的位置。
- 继续沿用已建立的零位与升降方向，起点为 M5/M6 的 `0`。没有保存辅助轴参数时沿用板端范围；不会凭目标脉冲猜测行程或重设零位。未连接、位置不符或其他任务占用时，在当前模块直接显示具体原因。
- 本批动作序号 `1/2/3`、二维码批次 `1/2` 可选择；每次只处理一个物料，不自动连续运行三个，也不自动递增序号。
- 任务码可手动输入；留空时使用本轮自动任务已锁定的二维码。没有二维码时允许按所选序号单独测试机构，视觉请求中相应没有颜色或放置标记约束。
- 停止、断开、取消使能、故障或超时取消本次动作，不自动复位或张开爪子。恢复前人工检查位置；再次启动仍要求两轴为 `0`。

## 动作顺序

抓取：S1 张开 → M5 下降至抓取位置 → S1 闭合 → M5 回最高点 → **M6 转至抓取转移位置，同时 S2 定位** → 两者均完成后 S1 张开 → M6 回原点。抓取第 1、2、3 次的 S2 默认角度分别为 `270°、135°、0°`；二维码颜色数字不是舵机角度编号，颜色 `4～6` 和重复颜色均可使用。

放置：S1 张开 → M6 转至车上取料位置 → S2 定位 → M5 下降至车上取料位置 → S1 闭合 → M5 回最高点并确认脉冲位置为0 → 等待0.5秒 → M6 回原点 → M5 下降至放料位置 → S1 张开 → M5 回最高点。最高点等待为固定时间，普通单件放置、C/D自动放置及第二次D叠放共用；等待期间仍可停止。第 1、2、3 次从车上取出时，S2 固定按 `0°、135°、270°` 的顺序；若调节了槽位角度，仍按抓取槽位的反序取出。

升降及旋转等待本次 `move_id` 的结束，并核对绝对脉冲位置；任何提前停止、编号变化或位置不符均中止。S2 与旋转共用一个阶段，两者都完成才松爪。S1/S2 为开环 PWM 舵机，当前到位依据是命令应答和可调等待时间，不是角度传感器测量。S1 继续通过物理映射使用 PH9/协议通道 2，S2 使用 PE4/协议通道 1。

## 完整参数

配置首次使用来自 `host/pick_place.py:DEFAULT`；保存后位于上位机 `host/pick_place.json`。使用自定义导航配置路径时，保存到同目录，方便模拟测试隔离。页面开放所有 19 项参数，三个下降位置和两个旋转目标独立设置。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `pick_down` | 9200 | 抓取下降位置，绝对脉冲 |
| `pick_rotation` | -1750 | 抓取转移旋转位置，绝对脉冲 |
| `place_take_down` | 9200 | 放置时从车上取料的下降位置 |
| `place_rotation` | -1750 | 放置时转至车上取料的旋转位置 |
| `place_drop_down` | 9200 | 放置时向场地放料的下降位置 |
| `lift_sps` / `lift_accel` | 300 / 1000 | 升降速度 step/s、加速度 step/s² |
| `rotation_sps` / `rotation_accel` | 300 / 1000 | 旋转速度与加速度 |
| `s1_open` / `s1_closed` | 120 / 75 | S1 张开、闭合角度 |
| `s2_slot_1` / `s2_slot_2` / `s2_slot_3` | 270 / 135 / 0 | 第 1、2、3 次抓取存放的槽位角度 |
| `s1_settle_ms` / `s2_settle_ms` | 600 / 1000 | 舵机收到应答后的稳定等待时间，待实机校准 |
| `step_timeout_ms` | 60000 | 单步超时；速度调低时须配套增加 |
| `ack_timeout_ms` | 3000 | 单条控制板应答超时 |
| `vision_timeout_ms` | 30000 | 等待视觉确认的超时 |

最高点与旋转原点保持 `0`。保存参数不发送运动指令，也不修改 M5/M6 范围或零位。运行时参数不可修改。

## 二维码与物料身份

任务码仍为 `抓取1+放置1+抓取2+放置2`。抓取组数字按采集顺序映射到 `270/135/0`；放置组数字按固定取出顺序 `0/135/270` 映射到目标标记。例：`156+231` 先抓红、黑、浅蓝；随后从 0° 取浅蓝放到标记 2，从 135° 取黑放到标记 3，从 270° 取红放到标记 1。

解析结果升级为 `schema: 2`：`batches[].items` 仍按固定取出顺序排列，含 `slot`（1=0°、2=135°、3=270°）、`pickup_index`、`angle_deg`、颜色与 `target`。新增 `pickup_items` 按实际抓取顺序排列。二维码预览与已锁定任务表同步反映该关系；解析结果仅表示分配，不表示物料已实际装车。

## 视觉接口

下面的 `require_vision=true` 是程序调用者主动使用的外部确认接口，不是手动测试按钮的工作模式，也不会自动启动相机或车身对准。调用者负责提交匹配确认；单纯在预览画面看到目标不会填写这个邮箱。B点自动取料由物料任务接入独立的下降后颜色确认流程，见 [B点取料](B_PICKUP.md)。

| 接口 | 用途 |
|---|---|
| `GET /api/pick-place/state` | `status`、完整 `config`、当前 `request` |
| `GET /api/pick-place/request` | 相同的只读快照，供视觉轮询 |
| `POST /api/pick-place/config` | `{"config": 完整配置}`，需要控制页身份 |
| `POST /api/pick-place/action` | `action: pick/place/stop`；需要控制页身份 |
| `POST /api/pick-place/vision` | `{"sample": 视觉结果}`；本机生产者可提交，远程保留控制页身份校验 |

启动示例（控制页通过现有 `X-Session` 或 `token` 身份提交）：

```json
{"action":"pick","batch":1,"item":1,"task_code":"156+231+516+123","require_vision":true}
```

调试页的 B 点完整抓取使用同一接口，并将 `profile` 设为 `b_pickup`；它只接受 `action: pick`，不等待视觉邮箱。省略 `profile` 仍使用通用抓放参数。

启动后只进入等待状态，不立即运动。视觉读取 `request`，根据其 `mode`、`color_id`（抓取）或 `target`（放置）识别并对准。结果样例中的任务编号和时间必须使用实时请求及真实采集时间：

```json
{"sample":{"job_id":"当前请求的 job_id","mode":"pick","batch":1,"item":1,"color_id":1,"ready":true,"captured_at":1792281600.0}}
```

`captured_at` 为 Unix 秒，需在当前请求发出后且最近 2 秒内；`job_id/mode/batch/item` 必须匹配，存在颜色或目标约束时也须匹配。旧任务、过期结果、错误目标、重复确认均被拒绝。写入视觉结果只更新邮箱，下一次上位机 tick 才进行新鲜的板端状态检查并开始动作。

`status.state`：`idle → vision（可选）→ preflight → arming（需要时）→ running → done`，异常为 `fault` 或 `stopped`。自动准备阶段允许未使能，进入运动阶段后解除使能仍会取消动作。`job_id` 每次不同，客户端必须用它匹配完成结果，不能把上次 `done` 当成本次成功。`context` 包含批次、动作序号、固定取出槽位、原抓取序号及可用的颜色/目标信息；`step/total/label` 展示进度。页面和 SSE 快照均可读取状态。

同进程接口：`Console.pick_place_action()`、`Console.pick_place_vision()` 和 `Console.pick_place.snapshot()`。这些入口复用同一状态机；没有第二套视觉专用电机代码。正式接入巡航挂起站点时，需要在上层增加明确的控制权交接，当前独立模块会拒绝与正在运行的巡航或视觉对准抢占控制。
